# Как запустить агента

Актуальное задание — **`agent/TASK-14.md`**. Следом готовы
**ТЗ-15, ТЗ-16, ТЗ-17 и ТЗ-18**: исполнитель берёт следующее сам, не
дожидаясь моей рецензии, — очереди хватит на пять ночей подряд. ТЗ-12 и
ТЗ-13 приняты и закрыты.

**Цель этой ночи в одной строке:** сборка снапшота перестаёт
просматривать все факты всех эмитентов ради одного — и пятьсот бумаг
из трёхчасовой затеи превращаются в обычный проход.

Файл для заказчика, не для агента.

### Главное: «периоды не сошлись» больше нет ни у кого

Тринадцать пропусков с этой причиной у шести эмитентов стали нулём.

| мера | было (ТЗ-11) | стало |
|---|---|---|
| чистая маржа | 20/20 | 20/20 |
| эффективная ставка налога | 20/20 | 20/20 |
| оборачиваемость активов | 20/20 | 20/20 |
| свободный денежный поток | 14/20 | **19/20** |
| рентабельность капитала | 18/20 | 16/20 — см. ниже, это честнее |
| EBITDA | 11/20 | **14/20** |
| NOPAT | 14/20 | 14/20 |
| операционная маржа | 14/20 | 14/20 |
| покрытие процентов | 12/20 | 12/20 |
| валовая маржа | 7/20 | 7/20 |

Два новых тега (Amazon и Tesla перешли на них годы назад) закрыли
капвложения и амортизацию. Правило «факт старше трёх лет с небольшим
во входы не годится» превратило вводящее в заблуждение «периоды не
сошлись» в честное «нет данных по операционной прибыли» у Berkshire и
J&J.

**Рентабельность капитала уменьшилась с 18 до 16 — и это исправление, а
не регресс.** У Visa и UnitedHealth свежего капитала в отчётности нет,
и прежние 18 включали две компании, которым прибыль 2025 года делили на
баланс 2009–2014 годов. Такое число хуже, чем его отсутствие.

### Находка ночи, и она важнее самих пунктов

Агент попробовал прогнать список из пятисот бумаг и обнаружил, что
проход не линейный, а квадратичный: **на каждую сборку снапшота
программа просматривает всю таблицу фактов целиком, причём дважды.**
Замер агента: 416 секунд на ста эмитентах, экстраполяция на пятьсот —
около трёх часов. Тест он оставил намеренно падающим, с объяснением,
вместо того чтобы подогнать или замолчать.

Я проверила структурно, а не по таймингам, и находка подтвердилась —
плюс к ней нашлось второе дно:

```
EXPLAIN QUERY PLAN: SCAN f / CORRELATED SCALAR SUBQUERY / SCAN a
индексы в схеме: []
```

**В базе нет ни одного индекса.** И тот же запрос не фильтруется по
эмитенту вовсе — то есть в «изменениях» снапшота Apple сейчас
показываются пересчёты всех остальных компаний. На двадцати тестовых
эмитентах это выглядит как медленный проход; на списке из пятисот это
неверный ответ на экране пользователя.

Обе половины чинит ТЗ-14: четыре именованных индекса миграцией 38 и
запрос, который спрашивает про одного эмитента.

### Спорные пункты

Спор был один — та самая находка про квадратичный проход, и он
**поддержан целиком**. Счёт по всем заходам: агент оказался прав в
двадцати спорах из двадцати одного.

Вопрос агента про Visa и UnitedHealth («не подставить ли капитал с
долей меньшинства, чтобы вернуть две рентабельности?») я **отклонила**:
знаменатель, который у двух компаний значит одно, а у восемнадцати
другое, ломает сравнение внутри группы. Вместо этого ТЗ-14 требует,
чтобы пропуск называл недостающий вход по имени — «нет данных: капитал»,
а не просто «нет данных».

Два мелких дефекта, найденных на ревью, тоже ушли пунктами ТЗ-14:
незаимпортированное имя в аннотации и первичный ключ новой таблицы,
который противоречит собственному комментарию.

**Про публикацию.** Всё запушено: `origin/agent/night-2` = `b90ac14`.

## 1. Что отправить исполнителю

Ключ и контакт этой ночью не нужны — **все пункты ТЗ-14 офлайновые**.
Проверять окружение перед запуском не обязательно.

```text
Ты автономный агент-исполнитель. Работаешь один, без связи со мной,
вопросов задавать некому. Обрыв сети, таймаут, исчерпанный лимит —
это пауза, а не конец работы.

Репозиторий: https://github.com/shemyakin925-ux/RusTerm.git

Выполни это до любых рассуждений и планов:

    git clone https://github.com/shemyakin925-ux/RusTerm.git
    cd RusTerm
    git checkout agent/night-2
    git merge origin/main
    python3 -m pip install pytest
    cat agent/TASK-14.md
    bash agent/acceptance.sh

Последняя команда обязана напечатать «пройдено 13, провалено 0».

При мерже возможны ровно два конфликта, оба в моих файлах: в
agent/LAUNCH.md и в agent/BACKLOG.md бери версию из main дословно
(git checkout origin/main -- agent/LAUNCH.md agent/BACKLOG.md).
Очередь бэклога я переписала руками — не восстанавливай старую.

Дальше работай строго по agent/TASK-14.md: раздел 1 (протокол) главнее
списка задач, пункты A1-A10 строго по порядку, один пункт — один
коммит — один пуш. Отчёт пиши в agent/REPORT-14.md по ходу дела и
только дописыванием в конец (§1.7 R1-R4), состояние — в
agent/STATE.json.

Твоя находка про квадратичный проход поддержана целиком и стала
первыми тремя пунктами ночи. В ней нашлась вторая половина: тот же
запрос не фильтруется по эмитенту, то есть выдаёт чужие пересчёты.
Читай §0.2 задания.

Сеть этой ночью не нужна ни одному пункту. Потратил запрос — объясни
в отчёте зачем.

Закончил все пункты A1-A9 раньше 09:30 — не жди меня и не выдумывай

Очередь: TASK-15, 16, 17, 18. У каждого свой файл отчёта
(REPORT-15/16/17/18) — в чужой отчёт не пиши. Задания 16, 17 и 18 ни от

В 10:00 по Дангану остановись и выполни раздел 3.
```

## 1a. Две переменные окружения

Обе читаются из окружения и **не коммитятся** — репозиторий публичный.

**1. Контакт для SEC EDGAR.** В `~/.rusterm.env`, права `600`. Этой
ночью не нужен ни одному пункту ТЗ-14; в ТЗ-15 его требует один пункт
(C6, потолок восемь запросов), в ТЗ-18 — половина пунктов (потолок сорок
запросов). Без контакта эти пункты корректно пропускаются, остальные
идут офлайн.

**2. Ключ модели.** Не требуется ни в одном из пяти заданий. ТЗ-16
закрывает вторую половину вехи M5 — «ни одна массовая операция не
исполняется без подтверждения», — и она целиком проверяется подставным
клиентом: настоящий вызов модели в задании прямо запрещён. Оставляйте
как есть.

## 2. Что проверить перед запуском

- **Доступ на запись.** Либо токен с правом записи, либо строка в
  сообщении: «пуш недоступен, утром отдай `git bundle create
  ../RusTerm-handoff.bundle --all` файлом».
- **Ветка на GitHub актуальна:** `origin/agent/night-2` = `b90ac14`.
- **Собираетесь закрыть репозиторий — сделайте это до запуска и дайте
  агенту токен.** Сейчас GitHub отдаёт `visibility: public`; после
  закрытия `git clone` в промпте перестанет работать без учётных данных
  и ночь умрёт на первой команде.
- **Всё, что агент запушит, станет публичным немедленно.**
- В контейнере есть `python3` 3.12 или новее и `git`.

## 3. Что сделать утром

```bash
cd RusTerm
git fetch origin && git checkout agent/night-2
git merge origin/main
bash agent/acceptance.sh
```

Дальше по порядку:

1. **Код возврата скрипта.** 0 — принято.
2. **`git diff origin/main -- agent/acceptance.sh`** — обязан быть
   пустым. Непустой означает, что агент правил приёмку; остальное
   можно не читать.
3. **`agent/ACCEPTANCE-12.txt`**, затем `agent/REPORT-14.md`, разделы
   «Disputed», «HANDOFF» и «What not to trust» — до раздела «Done».
4. **Команда, отвечающая на вопрос этой ночи:**

   ```bash
   python3 -m pytest tests/test_m4_scale.py -q -s
   ```

   Это тест на пятьсот бумаг. Ночью он должен перестать быть
   «намеренно падающим» и просто пройти — в отчёте обязано стоять
   фактическое время обоих проходов числами.
5. **Проверка, что чинили причину, а не симптом:**

   ```bash
   python3 -m pytest -q | tail -2
   ```

   Должно остаться **один** xfail вместо двух. Если их по-прежнему два,
   а тест на пятьсот бумаг «прошёл» — смотрите, не подняли ли потолок
   времени; задание это прямо запрещает.
6. **`git log --oneline origin/agent/night-2..agent/night-2`** — если
   непусто, работа не опубликована.
7. **Раздел «Disputed»** — за шесть заходов агент оказался прав в
   двадцати спорах из двадцати одного. Читайте раньше «Done».

Отчёт и скрипт расходятся — верить скрипту.

## 4. Что отправить рецензенту

Для независимой проверки — своё сообщение. Отдавать можно нескольким
моделям сразу, ответы сравнимы за счёт формата из `agent/REVIEW.md` §8.

```text
Проверь чужой проект как независимый рецензент. Код писали автономные
агенты, их отчёты содержат недостоверные утверждения — верь только тому,
что запустишь сам.

    git clone https://github.com/shemyakin925-ux/RusTerm.git
    cd RusTerm && git checkout agent/night-2
    python3 -m pip install pytest
    cat agent/REVIEW.md

agent/REVIEW.md — бриф проверки: что за проект, что реально сделано,
какие дефекты уже найдены, что смотреть и в каком виде отвечать.
Он самодостаточен, начни с него.

Ничего не чини и не коммить. Твоя задача — найти и описать, а не
исправить. Находка без способа воспроизвести — гипотеза, так её
и помечай.
```

Отправляй **одинаковый** текст каждой модели и сравнивай ответы:
находка, которую увидели двое независимо, почти наверняка настоящая;
одиночная — требует проверки.

## 5. Как запустить программу

### Сегодня это уже работает целиком

```bash
git clone https://github.com/shemyakin925-ux/RusTerm.git
cd RusTerm && git checkout agent/night-2
python3 -m venv .venv && .venv/bin/python -m pip install -e .
set -a; . ~/.rusterm.env; set +a

.venv/bin/rusterm init
.venv/bin/rusterm add --ticker AAPL --market US
.venv/bin/rusterm ingest --ticker AAPL --market US --source edgar
.venv/bin/rusterm snapshot --ticker AAPL --market US
.venv/bin/rusterm tui
```

`snapshot` выдаёт восемь-десять величин: чистая и операционная маржа,
эффективная ставка налога, EBITDA, свободный денежный поток, покрытие
процентов, рентабельность капитала, оборачиваемость активов — каждая с
годом, единицей измерения и ссылкой на исходный тег SEC. Пустые
называют причину поимённо. В `rusterm tui` по клавише `s` видно, откуда
взято каждое число.

**Новое со вчерашней ночи — обновление по расписанию:**

```bash
.venv/bin/rusterm refresh --watchlist <id> --dry-run   # ноль запросов, печатает план
.venv/bin/rusterm refresh --watchlist <id>             # один проход, для cron
```

Повторный прогон печатает «не изменилось» и **не скачивает ничего**:
сначала спрашивается дата последней отчётности (один маленький запрос),
и только при её сдвиге запрашиваются сами данные — с условным запросом,
на который сервер отвечает «не менялось» без тела. Демона в проекте нет
и не будет: это одна команда, её ставят в `cron`.

### Что в очереди дальше

- **ТЗ-15** — устаревший факт становится видимым в панели источника (а не
  просто исчезает из формулы), недостача мер привязывается к конкретным
  эмитентам вместо «пожелания», проход получает постоянного сторожа
  линейности.
- **ТЗ-16** — вторая половина вехи **M5**: намерение, четыре инструмента
  только на чтение, dry-run, подтверждение человеком, атомарное
  применение и строка аудита на каждую массовую операцию, включая
  отказанную. Первая половина (каждое число в тексте модели имеет ссылку)
  уже сделана и в задании только перепроверяется.
- **ТЗ-17** — веха **M7**: агрегат по сектору (p25 / медиана / p75 и
  число участников), который на историческую дату возвращает тот же
  состав и те же числа, потому что читает версию peer set и версии
  снапшотов, действовавшие тогда, а не сегодняшние.
- **ТЗ-18** — **Канада и OTC**, по вашему решению, плюс реестр рынков:
  `--market` перестаёт быть произвольной строкой и проверяется по
  таблице, а добавление следующего рынка после MVP стоит одной строки в
  ней, а не переписывания. Великобритания из вехи убрана по вашему
  указанию. Единственное задание в очереди, которому нужна сеть.

### Что даст ближайшая ночь

Список наблюдения перестанет упираться в размер. Сейчас каждая сборка
снапшота читает всю таблицу фактов целиком — на двадцати эмитентах это
незаметно, на пятистах это три часа. После ночи проход становится
линейным, а «изменения» в снапшоте компании перестают показывать чужие
пересчёты.

**Интерфейс терминальный, а не оконный** — решение принято в ТЗ-8 U11
и записано в ADR-0009: TUI на `curses` сейчас, десктоп на PySide6
остаётся заявленной целью ADR-0004.
