# Как запустить агента

Актуальное задание — **`agent/TASK-8.md`**, одно на всю ночь. ТЗ-7
принято и закрыто, открывать его снова не нужно.

**Цель этой ночи названа в первой строке задания:** утром вы ставите
программу одной командой, запускаете `rusterm` и работаете со своими
компаниями, а не с единственной синтетической `US-CLI-DEMO`.

Четырнадцать пунктов U0-U13 строго по приоритету, дальше
`agent/BACKLOG.md`. Порядок такой: сначала три дефекта, которые молча
портят то, что увидит пользователь; потом то, без чего программой
нельзя пользоваться в принципе (работа по выбранному инструменту и
чтение `~/.rusterm.env` самим приложением); потом установка и README —
они стоят намеренно раньше сетевого блока, чтобы даже короткая ночь
оставила вам работающую программу; потом реальные данные SEC (вехи M2
и M3); потом терминальный интерфейс. Работы заведомо больше, чем на
ночь. Финальную приёмку агент прогоняет сам и кладёт
в `agent/ACCEPTANCE-6.txt`.

Задание самодостаточно: способ работы встроен внутрь, `SKILL.md`
и прежние ТЗ читать не нужно.

Одно готовое ТЗ, а не два. Правило «держать два задания вперёд»
сознательно нарушено: ТЗ-7 показало, что одно большое упорядоченное
задание плюс `agent/BACKLOG.md` как переполнение работает лучше двух
READY-файлов, между которыми автономный агент вынужден выбирать.

Для отдачи на независимую проверку — `agent/REVIEW.md`, раздел 4 ниже.

Файл для заказчика, не для агента.

## 1. Что отправить исполнителю

Сначала — **в той же оболочке, из которой запускаете агента**:

```bash
set -a; . ~/.rusterm.env; set +a
printenv RUSTERM_SEC_UA | cut -c1-12   # должно напечатать начало контакта
```

Если вторая команда молчит — агент опять уйдёт по синтетическому пути,
и ночь опять потеряет сетевые пункты. Это единственная подготовка,
которая реально решает исход ночи.

```text
Ты автономный агент-исполнитель. Работаешь один, без связи со мной,
вопросов задавать некому. Обрыв сети, таймаут, исчерпанный лимит —
это пауза, а не конец работы.

Репозиторий: https://github.com/shemyakin925-ux/RusTerm.git

Выполни это до любых рассуждений и планов:

    git clone https://github.com/shemyakin925-ux/RusTerm.git
    cd RusTerm
    git checkout agent/night-2
    git merge origin/main
    printenv RUSTERM_SEC_UA | cut -c1-12
    python3 -m pip install pytest
    cat agent/TASK-8.md
    bash agent/acceptance.sh

Предпоследняя команда обязана напечатать начало контакта для SEC.
Напечатала пусто — работай по синтетическому пути и запиши это фактом,
как велит §1.12 N2 задания. Придумывать контакт запрещено.

Последняя команда обязана напечатать «пройдено 13, провалено 0».
Конфликт при мерже возможен ровно один, в agent/LAUNCH.md, — это мой
файл, бери версию из main дословно, команда есть в §0 задания.

Дальше работай строго по agent/TASK-8.md: раздел 1 (протокол) главнее
списка задач, пункты U0-U13 строго по порядку, один пункт — один
коммит — один пуш. Отчёт пиши в agent/REPORT-8.md по ходу дела,
состояние — в agent/STATE.json. В 10:00 по Дангану остановись и
выполни раздел 3 задания.
```

## 1a. Что задать перед запуском: две переменные окружения

Обе читаются из окружения и **не коммитятся** — репозиторий публичный.
Если переменная не задана, соответствующая ветка деградирует на
синтетику, это записывается фактом в отчёт и ночь не блокирует.

`~/.rusterm.env` уже лежит вне репозитория, права `600`, и задаёт
`RUSTERM_SEC_UA`. Прошлой ночью его никто не подгрузил — отсюда потеря
пяти пунктов. Поэтому команда из раздела 1 обязательна:

```bash
set -a; . ~/.rusterm.env; set +a
```

После пункта U4 этой ночи само приложение будет читать `~/.rusterm.env`,
если переменной нет в окружении, — и `rusterm doctor` покажет, откуда
взята каждая из трёх переменных (из окружения, из файла или ниоткуда),
**не показывая значений**. Для агента же оболочку всё равно нужно
подготовить: он читает `RUSTERM_SEC_UA` до того, как U4 будет написан.

**1. Контакт для SEC EDGAR — без него в сеть агент не пойдёт.**

SEC требует `User-Agent` с настоящим контактом, иначе блокирует
запросы. В `~/.rusterm.env` ваш адрес уже подставлен:

```bash
export RUSTERM_SEC_UA="Имя Фамилия ваш@адрес.почты"   # в файле — реальный
```

В сам репозиторий адрес не вписан: он уехал бы в логи SEC и в git.
Выдуманный адрес хуже, чем отсутствие сети — ТЗ прямо запрещает агенту
сочинять контакт.

**2. Ключ модели для самого приложения — сейчас его в файле нет.**

Хотите, чтобы LLM-слой проверился на настоящей модели, — допишите
в `~/.rusterm.env` две строки:

```bash
export RUSTERM_LLM_PROVIDER=<провайдер>
export RUSTERM_LLM_API_KEY=<ключ>
```

Это ваши деньги: каждый вызов платный. В ТЗ жёсткий потолок — **50
вызовов за ночь**, счётчик в `STATE.json`, дальше отказ. Без ключа
строится и проверяется детерминированная половина, и она в этой ночи
важнее: пункт U0 чинит предохранитель, который сейчас пропускает
выдуманные числа. Настоящую модель имеет смысл включать после того,
как U0 закрыт.

Ограничения на сеть, прописанные в ТЗ §1.12, чтобы вас не заблокировали
у первоисточника: только SEC EDGAR, 5 запросов в секунду при
разрешённых десяти, жёсткий потолок 5000 запросов за ночь с отказом,
а не засыпанием; 403 и 429 — остановка и запись, без смены User-Agent,
прокси и зеркал; скачанное никогда не попадает в git и никогда не
попадает в `fixtures/`, где всё помечено синтетикой.

## 2. Что проверить перед запуском

- **Доступ на запись — главное.** Прошлый заход отработал всю ночь и
  не запушил ни одного коммита: работа уцелела только потому, что
  осталась на этом ноутбуке. Выдай токен с правом записи либо впиши
  в сообщение отдельной строкой: «пуш недоступен, утром отдай
  `git bundle create handoff.bundle --all` файлом».
- **Ветка на GitHub актуальна:** `origin/agent/night-2` = `81c7068`,
  вся работа ночи опубликована. Проверить: `git fetch origin && git log
  --oneline -1 origin/agent/night-2`.
- **Собираетесь закрыть репозиторий — сделайте это до запуска и дайте
  агенту токен.** Сейчас GitHub отдаёт `visibility: public`; попытка
  переключения не применилась. Как только репозиторий станет приватным,
  `git clone` в промпте запуска перестанет работать без учётных данных,
  и ночь умрёт на первой же команде. Порядок такой: закрыть
  репозиторий → выдать токен с правами `repo` → проверить клон самому,
  чистой командой, и только потом запускать агента.
- **Всё, что агент запушит, станет публичным немедленно** (пока
  репозиторий открыт). Отозвать
  опубликованное нельзя: форки и зеркала остаются. Поэтому запрет
  выдумывать данные и требование помечать фикстуры синтетическими —
  не гигиена, а защита от того, что придуманное число уедет наружу
  под видом отчётности эмитента. Сейчас правило соблюдено: все пять
  файлов в `fixtures/` помечены `synthetic` и в имени, и внутри.
- В контейнере есть `python3` версии 3.12 или новее и `git`.
- `pytest` ставится из сети. Не встанет — агент по заданию обязан
  продолжить и записать это; проверка 3 тогда не пройдёт, и это
  честный результат, а не провал.

## 3. Что сделать утром

```bash
cd RusTerm
git fetch origin && git checkout agent/night-2
git merge origin/main            # без этого проверка 10 краснеет законно
bash agent/acceptance.sh
```

Мерж в первой строке обязателен: в `main` лежит правка
`docs/governance-thresholds.md` по итогам разбора спорных пунктов, и до
мержа проверка 10 честно показывает, что ветка отстала от документа.

Дальше по порядку:

1. **Код возврата скрипта.** 0 — принято. Иначе он сам печатает,
   что именно не сошлось.
2. **`git diff origin/main -- agent/acceptance.sh`** — обязан быть
   пустым. Непустой означает, что агент правил приёмку; всё остальное
   после этого можно не читать.
3. **`agent/ACCEPTANCE-6.txt`** — прогон приёмки, который агент сделал
   сам. Затем `agent/REPORT-8.md`, разделы «HANDOFF» и «What not to
   trust» — до раздела «Done».
4. **`git log --oneline origin/agent/night-2..agent/night-2`** — если
   непусто, работа не опубликована, см. раздел 0.
5. **Раздел «Disputed»** в отчёте — там места, где агент считает
   задание или скрипт неправыми. За два последних захода он оказался
   прав в семи спорах из девяти — читайте этот раздел раньше «Done».

Отчёт и скрипт расходятся — верить скрипту.

## 4. Что отправить рецензенту

Для независимой проверки — своё сообщение. Отдавать можно нескольким
моделям сразу, ответы сравнимы за счёт формата из `agent/REVIEW.md` §8.

```text
Проверь чужой проект как независимый рецензент. Код писали автономные
агенты, их отчёты содержат недостоверные утверждения — верь только тому,
что запустишь сам.

    git clone https://github.com/shemyakin925-ux/RusTerm.git
    cd RusTerm && git checkout agent/night-2
    python3 -m pip install pytest
    cat agent/REVIEW.md

agent/REVIEW.md — бриф проверки: что за проект, что реально сделано,
какие дефекты уже найдены, что смотреть и в каком виде отвечать.
Он самодостаточен, начни с него.

Ничего не чини и не коммить. Твоя задача — найти и описать, а не
исправить. Находка без способа воспроизвести — гипотеза, так её
и помечай.
```

Отправляй **одинаковый** текст каждой модели и сравнивай ответы:
находка, которую увидели двое независимо, почти наверняка настоящая;
одиночная — требует проверки.

## 5. Как запустить программу — сегодня и после этой ночи

### Сегодня программа уже ставится и запускается

Проверено мной прямо сейчас на чистой выкладке `origin/agent/night-2`,
команды ниже выполнены, вывод настоящий:

```bash
git clone https://github.com/shemyakin925-ux/RusTerm.git
cd RusTerm
git checkout agent/night-2
python3 -m venv .venv && .venv/bin/python -m pip install -e .
.venv/bin/rusterm --help
```

Дальше рабочий цикл на демо-данных:

```bash
.venv/bin/rusterm --root ~/rusterm-data init
.venv/bin/rusterm --root ~/rusterm-data ingest
.venv/bin/rusterm --root ~/rusterm-data snapshot
.venv/bin/rusterm --root ~/rusterm-data coverage US-CLI-DEMO
```

Что вы увидите: `применено миграций: 34; schema_version=35`,
`фактов: 4`, `снапшот v1`, и восемь строк покрытия с причинами.

**И почему пользоваться этим пока нельзя.** Во-первых, `ingest`,
`snapshot` и `export` зашиты на единственную синтетическую компанию
`US-CLI-DEMO` — что бы вы ни добавили в список наблюдения, считается
она. Во-вторых, демо ничего не показывает: три меры записаны, все три
пустые, а покрытие честно пишет «фундаментальных данных нет». То есть
каркас работает, а смотреть в нём не на что. Ровно это и чинят пункты
U3, U9 и U10 ближайшей ночи.

### После этой ночи — то, ради чего она

```bash
pip install -e .
rusterm                       # что это и четыре команды нормального пути
rusterm init
rusterm watchlist create my --name "Мой список"
rusterm watchlist add my --ticker AAPL --market US
rusterm ingest --watchlist my --source edgar
rusterm snapshot --watchlist my
rusterm status                # что у меня есть: инструменты, снапшоты, покрытие
rusterm tui                   # список наблюдения и карточка компании в терминале
```

Пункты идут по приоритету, поэтому даже короткая ночь оставляет
работающее: сначала чинятся дефекты (U0-U2), потом снимается привязка
к демо и приложение учится само читать `~/.rusterm.env` (U3, U4), потом
установка и README (U9, U10) — на этом месте программой уже можно
пользоваться на синтетике. Реальные данные SEC (U5-U8) и терминальный
интерфейс (U11) идут после. Если ночь оборвётся на U6, у вас всё равно
будет установленная программа с командами выше, просто без данных SEC
и без TUI.

**Интерфейс будет терминальный, а не оконный.** ADR-0004 выбрал
PySide6, но проверка 6 в скрипте приёмки запрещает Qt в дереве, и
менять скрипт нельзя. Решение принято мной и записано в ТЗ пунктом
U11: сейчас строится TUI на `curses` из стандартной библиотеки,
десктоп остаётся заявленной целью, расхождение фиксируется отдельным
ADR-0009. Название проекта — RusTerm — этому не противоречит.
