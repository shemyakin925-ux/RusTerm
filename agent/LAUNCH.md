# Как запустить агента

Актуальное задание — **`agent/TASK-10.md`**. Следом за ним, на случай
что ночь окажется короче работы, лежит готовое **`agent/TASK-11.md`**:
исполнитель берёт его сам, не дожидаясь моей рецензии. ТЗ-9 принято
и закрыто.

**Цель этой ночи в одной строке:** записанные ответы SEC должны нести
все теги, которые нужны формулам, — тогда девять формул, написанных
прошлой ночью, перестанут возвращать «нет данных» на двадцати
настоящих эмитентах.

Порядок такой: сначала W0 — падение в команде, которой человек
пользуется первой, двадцать минут работы; потом W1 и W2 — инструмент
обрезки и перезагрузка payload'ов, это и есть ночь; дальше пункты,
которые ничего не добавляют к возможностям программы, но чинят
найденное. Финальную приёмку агент прогоняет сам и кладёт в
`agent/ACCEPTANCE-8.txt`.

Два готовых ТЗ, а не одно, — и это отход от прошлой записи в этом
файле. Причина конкретная: прошлой ночью исполнитель дошёл до конца
списка и остановился, имея время. Правило `CLAUDE.md` о двух заданиях
вперёд написано ровно для этого, а прежнее возражение — «выбор мешает
работать» — снято тем, что `TASK-11.md` первой же строкой запрещает
начинать с себя.

Файл для заказчика, не для агента.

### Спор про J&J: агент остановился правильно, а объяснил неверно

Это самый интересный пункт смены, и он стоил одного запроса к SEC,
чтобы закрыть его окончательно.

Агент перезагрузил данные Johnson & Johnson, увидел, что выручка за
2021 год стала 78 740 вместо 93 775 миллионов, счёл это переписыванием
истории на стороне SEC и **остановился, не тронув проверочное
значение**. Остановка абсолютно правильная, ровно для этого правило

Но SEC ничего не переписывал. Я запросила живой фид: за тот же период
там лежат **три** записи, по одной на каждую отчётность, где этот
период показывали:

| значение | отчётность | подана |
|---|---|---|
| 93 775 000 000 | `0000200406-22-000022` | 17.02.2022 |
| 93 775 000 000 | `0000200406-23-000016` | 16.02.2023 |
| 78 740 000 000 | `0000200406-24-000013` | 16.02.2024 |

Исходная запись на месте и не изменилась. Третья — это пересчёт «по
продолжающейся деятельности» после отделения Kenvue: тоже правда, но
другая база того же периода. Изменилась не отчётность, а **обрезка**:
первый раз она оставила самую раннюю запись периода, второй — самую
свежую.

В проекте для этого давно есть колонка `basis` со значениями
«как отчитались» и «пересчитано», и выборка величин уже фильтрует по
первому. То есть модель данных была в порядке всё это время. Мои
решения: проверочные значения из пересчётов не берутся никогда,
обрезка становится инструментом и учится держаться за номер
отчётности, а золотой файл перестаёт искать значение по индексу
массива. Всё это — W1 и W2.

## 1a. Что задать перед запуском: две переменные окружения

Обе читаются из окружения и **не коммитятся** — репозиторий публичный.
Если переменная не задана, соответствующая ветка деградирует на
офлайн-путь, это записывается фактом в отчёт и ночь не блокирует.

**1. Контакт для SEC EDGAR.** В `~/.rusterm.env` задан, права `600`,
проверено. Ничего делать не нужно, кроме команды из раздела 1. В эту
ночь он важнее обычного: без него W2 не выполняется.

**2. Ключ модели.** В ТЗ-10 его не требует ни один пункт — веха M5
не входит в задание этой ночи. Оставляйте как есть; решение можно
принять на следующей смене.

Ограничения на сеть, прописанные в ТЗ §1.12, чтобы вас не заблокировали
у первоисточника: только SEC EDGAR, 5 запросов в секунду при
разрешённых десяти, жёсткий потолок 5000 запросов за ночь с отказом,
а не засыпанием; 403 и 429 — остановка и запись, без смены User-Agent,
прокси и зеркал; скачанное не попадает в git, кроме обрезанных
записанных ответов в `tests/data/edgar/`, и никогда не попадает в
`fixtures/`, где всё помечено синтетикой. Эта ночь тратит около
двадцати запросов.

## 2. Что проверить перед запуском

- **Доступ на запись.** Либо токен с правом записи, либо строка в
  сообщении: «пуш недоступен, утром отдай `git bundle create
  ../RusTerm-handoff.bundle --all` файлом».
- **Ветка на GitHub актуальна:** `origin/agent/night-2` = `cf1919b`,
  вся работа прошлой смены опубликована.
- **Собираетесь закрыть репозиторий — сделайте это до запуска и дайте
  агенту токен.** Сейчас GitHub отдаёт `visibility: public`. Как только
  репозиторий станет приватным, `git clone` в промпте запуска перестанет
  работать без учётных данных, и ночь умрёт на первой же команде.
  Порядок: закрыть репозиторий → выдать токен с правами `repo` →
  проверить клон самому, чистой командой, и только потом запускать.
- **Всё, что агент запушит, станет публичным немедленно.** Отозвать
  опубликованное нельзя: форки и зеркала остаются. Поэтому запрет
  выдумывать данные — не гигиена, а защита от того, что придуманное
  число уедет наружу под видом отчётности эмитента.
- В контейнере есть `python3` версии 3.12 или новее и `git`.
- `pytest` ставится из сети. Не встанет — агент по заданию обязан
  продолжить и записать это; проверка 3 тогда не пройдёт, и это
  честный результат, а не провал.

## 3. Что сделать утром

```bash
cd RusTerm
git fetch origin && git checkout agent/night-2
git merge origin/main
bash agent/acceptance.sh
```

Дальше по порядку:

1. **Код возврата скрипта.** 0 — принято. Иначе он сам печатает,
   что именно не сошлось.
2. **`git diff origin/main -- agent/acceptance.sh`** — обязан быть
   пустым. Непустой означает, что агент правил приёмку; всё остальное
   после этого можно не читать.
3. **`agent/ACCEPTANCE-8.txt`** — прогон приёмки, который агент сделал
   сам. Затем `agent/REPORT-10.md`, разделы «HANDOFF», «Disputed» и
   «What not to trust» — до раздела «Done».
4. **Одна команда, которая отвечает на вопрос этой ночи:**

   ```bash
   python3 -m pytest tests/test_m3_snapshot.py -q -s
   ```

   Он теперь обязан падать, если хоть одна из десяти величин не
   набрала свой порог, и печатать таблицу «мера → сколько из двадцати».
   Зелёный — значит формулы накормлены и на экране не одна маржа,
   а весь набор.
5. **Одна команда, которая проверяет, что J&J не поехал:**

   ```bash
   git diff origin/main -- tests/data/golden_m2.json | grep '^[-+].*expected'
   ```

   Обязана быть пустой. Непустая означает, что проверочное значение
   всё-таки правили, — а это единственное, чего в этой ночи делать
   нельзя ни при каких обстоятельствах.
6. **`git log --oneline origin/agent/night-2..agent/night-2`** — если
   непусто, работа не опубликована.
7. **Раздел «Disputed»** в отчёте — там места, где агент считает
   задание или скрипт неправыми. За четыре захода он оказался прав в
   одиннадцати спорах из тринадцати — читайте этот раздел раньше «Done».

Отчёт и скрипт расходятся — верить скрипту.

## 5. Как запустить программу — сегодня и после этой ночи

### Сегодня: своя компания заводится офлайн, числа — одна маржа

```bash
git clone https://github.com/shemyakin925-ux/RusTerm.git
cd RusTerm && git checkout agent/night-2
python3 -m venv .venv && .venv/bin/python -m pip install -e .
.venv/bin/rusterm init
.venv/bin/rusterm add --ticker AAPL --market US --cik 320193 --name "Apple Inc."
.venv/bin/rusterm snapshot --ticker AAPL --market US
.venv/bin/rusterm tui
```

Я прошла это руками: инструмент создаётся, повторный запуск говорит
«уже существует» и не дублирует, снапшот строится.

Две оговорки, обе честные:

- **`--cik` и `--name` обязательны**, хотя не должны быть: с заданным
  контактом SEC команда обязана добирать их сама, и именно этот путь
  падает (пункт 0 раздела 0). Чинится первым пунктом ночи.
- **Числа будут только там, где хватило тегов** — сегодня это чистая
  маржа. Остальное скажет «нет данных» и назовёт причину. Это и есть
  предмет ночи.

Демо-путь тоже на месте и работает: `rusterm demo`, дальше `ingest` и
`snapshot` по `US-CLI-DEMO`. Программа сама предупреждает, что данные
демо синтетические.

### После этой ночи — то, ради чего она

```bash
rusterm add --ticker AAPL --market US        # без --cik и --name
rusterm ingest --ticker AAPL --market US --source edgar
rusterm snapshot --ticker AAPL --market US
rusterm tui
```

И `snapshot` выдаёт не одну величину, а весь набор: операционная маржа,
эффективная ставка налога, валовая маржа, EBITDA, свободный денежный
поток, покрытие процентов, рентабельность капитала — каждая с годом,
из которого посчитана, с единицей измерения и со ссылкой на тег SEC.
`rusterm tui` показывает их в карточке, а по клавише `s` — откуда взято
каждое число: документ, локатор, исходный тег и версия маппинга.

Пункты идут по приоритету, поэтому даже короткая ночь оставляет
работающее: W0 чинит команду за двадцать минут, W1 делает обрезку
воспроизводимой и без сети. Оборвётся на W2 — у вас всё равно будет
рабочая `add` и инструмент, которым перезагрузку можно повторить
следующей сменой одной командой.

**Интерфейс терминальный, а не оконный** — решение принято в ТЗ-8 U11
и записано в ADR-0009: TUI на `curses` сейчас, десктоп на PySide6
остаётся заявленной целью ADR-0004. Название проекта — RusTerm — этому
не противоречит.
