## 23.09, ночь: разрешения ожили, страж вернулся на доработку

**Принят пункт про «немые разрешения».** Исполнитель написал проверку,
которая ловит мою давнюю ошибку в формулировках, и сделал больше, чем

там второй путь был мёртвым. Обе починила: теперь один путь на строку,
проверено самим скриптом.

**Один пункт вернула — по иронии, за ту же болезнь, которую он лечил.**
Тест, следящий за границей круга, оказался привязан к «самому свежему»
коммиту эстафеты. Пока сверху стояла нужная отметка, он был зелёным; моя
же передача хода подняла туда следующую — и тест покраснел, сам не
изменившись. Починила, а исполнителю вернула правило: **проверка не
вправе зависеть от того, сколько кругов прошло после её написания.**

**Скажу прямо о накопившемся.** Это третий раз подряд, когда красная
проверка запирает передачу хода с обеих сторон, и чинить приходится мне
на месте. Механизм эстафеты устроен так, что дефект в сторожах
останавливает саму работу. Поэтому в новое задание добавила пункт:
при отказе передачи показывать **имена упавших тестов**, а не одну фразу
«приёмка красная» — три круга подряд разбор начинался с раскопок.

Плюс отдельный пункт на давний артефакт: проверка в «подключённом»
рабочем каталоге падает там, где в обычном клоне всё зелено. Это описано
в заметках, но ни разу не измерено — теперь измерим и либо починим, либо
честно пропустим с причиной.

**Очередь:** ТЗ-80 → ТЗ-77 (воспроизводимая база) → ТЗ-73 → ТЗ-74.


**1. Рынки Кореи, Бразилии, Австралии и углубление US-OTC.**

500 бумаг в 800 запросов не помещается, а ваша схема — с запасом.

### Находка ночи, и она важнее самих пунктов

Агент попробовал прогнать список из пятисот бумаг и обнаружил, что
проход не линейный, а квадратичный: **на каждую сборку снапшота
программа просматривает всю таблицу фактов целиком, причём дважды.**
Замер агента: 416 секунд на ста эмитентах, экстраполяция на пятьсот —
около трёх часов. Тест он оставил намеренно падающим, с объяснением,
вместо того чтобы подогнать или замолчать.

Я проверила структурно, а не по таймингам, и находка подтвердилась —
плюс к ней нашлось второе дно:

```
EXPLAIN QUERY PLAN: SCAN f / CORRELATED SCALAR SUBQUERY / SCAN a
индексы в схеме: []
```

**В базе нет ни одного индекса.** И тот же запрос не фильтруется по
эмитенту вовсе — то есть в «изменениях» снапшота Apple сейчас
показываются пересчёты всех остальных компаний. На двадцати тестовых
эмитентах это выглядит как медленный проход; на списке из пятисот это
неверный ответ на экране пользователя.

Обе половины чинит ТЗ-14: четыре именованных индекса миграцией 38 и
запрос, который спрашивает про одного эмитента.

## 5. Как запустить программу

### Сегодня это уже работает целиком

```bash
git clone https://github.com/shemyakin925-ux/RusTerm.git
cd RusTerm && git checkout agent/night-2
python3 -m venv .venv && .venv/bin/python -m pip install -e .
set -a; . ~/.rusterm.env; set +a

.venv/bin/rusterm init
.venv/bin/rusterm add --ticker AAPL --market US
.venv/bin/rusterm ingest --ticker AAPL --market US --source edgar
.venv/bin/rusterm snapshot --ticker AAPL --market US
.venv/bin/rusterm tui
```

`snapshot` выдаёт восемь-десять величин: чистая и операционная маржа,
эффективная ставка налога, EBITDA, свободный денежный поток, покрытие
процентов, рентабельность капитала, оборачиваемость активов — каждая с
годом, единицей измерения и ссылкой на исходный тег SEC. Пустые
называют причину поимённо. В `rusterm tui` по клавише `s` видно, откуда
взято каждое число.

**Новое со вчерашней ночи — обновление по расписанию:**

```bash
.venv/bin/rusterm refresh --watchlist <id> --dry-run   # ноль запросов, печатает план
.venv/bin/rusterm refresh --watchlist <id>             # один проход, для cron
```

Повторный прогон печатает «не изменилось» и **не скачивает ничего**:
сначала спрашивается дата последней отчётности (один маленький запрос),
и только при её сдвиге запрашиваются сами данные — с условным запросом,
на который сервер отвечает «не менялось» без тела. Демона в проекте нет
и не будет: это одна команда, её ставят в `cron`.

### Что в очереди дальше

- **ТЗ-15** — устаревший факт становится видимым в панели источника (а не
  просто исчезает из формулы), недостача мер привязывается к конкретным

### Что даст ближайшая ночь

Список наблюдения перестанет упираться в размер. Сейчас каждая сборка
снапшота читает всю таблицу фактов целиком — на двадцати эмитентах это
незаметно, на пятистах это три часа. После ночи проход становится
линейным, а «изменения» в снапшоте компании перестают показывать чужие
пересчёты.

**Интерфейс терминальный, а не оконный** — решение принято в ТЗ-8 U11
и записано в ADR-0009: TUI на `curses` сейчас, десктоп на PySide6
остаётся заявленной целью ADR-0004.
