# Как запустить агента

Актуальное задание — **`agent/TASK-9.md`**, одно на всю ночь. ТЗ-8
принято и закрыто, открывать его снова не нужно.

**Цель этой ночи названа в первой строке задания:** двадцать настоящих
американских эмитентов должны выйти из `snapshot` **с числами**, а не с
тремя пустыми мерами каждый.

Девять пунктов V0–V9 строго по приоритету, дальше `agent/BACKLOG.md`.
Порядок такой: сначала четыре пункта, которые превращают пустые
снапшоты в непустые и дают человеку способ завести свою компанию, —
все четыре работают **офлайн, на уже лежащих в git данных SEC**, и
ночь, оборвавшаяся после V3, уже дала главное; потом расширение набора
величин; потом сеть; потом видимость маппинга пользователю; потом
модель (нужен ключ); в конце — бухгалтерия отчёта. Финальную приёмку
агент прогоняет сам и кладёт в `agent/ACCEPTANCE-7.txt`.

Задание самодостаточно: способ работы встроен внутрь, `SKILL.md`
и прежние ТЗ читать не нужно.

Одно готовое ТЗ, а не два — сознательно, второй раз подряд. Правило
«держать два задания вперёд» из `CLAUDE.md` проверено дважды и дважды
проиграло: одно большое упорядоченное задание плюс `agent/BACKLOG.md`
как переполнение даёт автономному агенту меньше поводов выбирать и
больше поводов работать.

Файл для заказчика, не для агента.

Сначала — **в той же оболочке, из которой запускаете агента**:

```bash

printenv RUSTERM_SEC_UA | cut -c1-12   # должно напечатать начало контакта
```

С этой ночи это уже не единственная защита: приложение само читает
`~/.rusterm.env`, если переменной нет в окружении. Но агент читает
`RUSTERM_SEC_UA` и своей рукой, из оболочки, — поэтому команда выше
по-прежнему стоит тридцати секунд.


## 1a. Что задать перед запуском: две переменные окружения

Обе читаются из окружения и **не коммитятся** — репозиторий публичный.
Если переменная не задана, соответствующая ветка деградирует на
офлайн-путь, это записывается фактом в отчёт и ночь не блокирует.

**1. Контакт для SEC EDGAR.** В `~/.rusterm.env` уже задан, права `600`,
проверено `rusterm doctor` прошлой ночью. Ничего делать не нужно, кроме
команды из раздела 1.

**2. Ключ модели — вот это решение за вами, и оно единственное.**

Пункт V7 (веха M5) — единственный в ТЗ-9, который **не может быть
сделан без вас**. Сейчас в `~/.rusterm.env` объявлен только контакт SEC,
поэтому агент по правилу задания пропустит V7 и запишет
`LLM key unset — M5 not exercised`. Хотите, чтобы LLM-слой проверился
на настоящей модели — допишите в `~/.rusterm.env` две строки:

```bash
export RUSTERM_LLM_PROVIDER=<провайдер>
export RUSTERM_LLM_API_KEY=<ключ>
```

Это ваши деньги: каждый вызов платный. В ТЗ жёсткий потолок — **50
вызовов за ночь**, счётчик в `STATE.json`, дальше отказ; самому пункту
V7 хватает двух. Ключ по заданию не имеет права попасть ни в коммит,
ни в лог, ни в отчёт, ни в тест.

Моя рекомендация: **можно и не давать**. V7 стоит восьмым из девяти,
и вся ценность этой ночи — в V0–V5, которые ключа не требуют. Пустой
ключ не отнимет у ночи ничего, кроме одной вехи, которую можно взять
следующей сменой одним коротким заданием.

Ограничения на сеть, прописанные в ТЗ §1.12, чтобы вас не заблокировали
у первоисточника: только SEC EDGAR, 5 запросов в секунду при
разрешённых десяти, жёсткий потолок 5000 запросов за ночь с отказом,
а не засыпанием; 403 и 429 — остановка и запись, без смены User-Agent,
прокси и зеркал; скачанное не попадает в git, кроме обрезанных
записанных ответов в `tests/data/edgar/`, и никогда не попадает в
`fixtures/`, где всё помечено синтетикой.

## 2. Что проверить перед запуском

- **Доступ на запись.** Прошлая смена запушила всё, кроме последних
  двух коммитов, и только потому, что в конце пропала сеть. Правило
  прежнее: либо токен с правом записи, либо строка в сообщении:
  «пуш недоступен, утром отдай `git bundle create
  ../RusTerm-handoff.bundle --all` файлом».
- **Ветка на GitHub актуальна:** `origin/agent/night-2` = `8c2f5b5`,
  вся работа смены опубликована, я досылала хвост руками.
- **Собираетесь закрыть репозиторий — сделайте это до запуска и дайте
  агенту токен.** Сейчас GitHub отдаёт `visibility: public`. Как только
  репозиторий станет приватным, `git clone` в промпте запуска перестанет
  работать без учётных данных, и ночь умрёт на первой же команде.
  Порядок: закрыть репозиторий → выдать токен с правами `repo` →
  проверить клон самому, чистой командой, и только потом запускать.
- **Всё, что агент запушит, станет публичным немедленно.** Отозвать
  опубликованное нельзя: форки и зеркала остаются. Поэтому запрет
  выдумывать данные — не гигиена, а защита от того, что придуманное
  число уедет наружу под видом отчётности эмитента. Сейчас правило
  соблюдено: `fixtures/` помечены `synthetic`, а всё, что в
  `tests/data/edgar/`, — настоящие ответы SEC с ссылкой на источник.
- В контейнере есть `python3` версии 3.12 или новее и `git`.
- `pytest` ставится из сети. Не встанет — агент по заданию обязан
  продолжить и записать это; проверка 3 тогда не пройдёт, и это
  честный результат, а не провал.

## 3. Что сделать утром

```bash
cd RusTerm
```

Мерж в первой строке обязателен: в `main` лежит правка

Дальше по порядку:

1. **Код возврата скрипта.** 0 — принято. Иначе он сам печатает,

2. **`git diff origin/main -- agent/acceptance.sh`** — обязан быть
   пустым. Непустой означает, что агент правил приёмку; всё остальное
   после этого можно не читать.
3. **`agent/ACCEPTANCE-7.txt`** — прогон приёмки, который агент сделал
   сам. Затем `agent/REPORT-9.md`, разделы «HANDOFF» и «What not to
   trust» — до раздела «Done».
4. **Одна команда, которая отвечает на вопрос этой ночи:**

   ```bash
   python3 -m pytest tests/test_m3_snapshot.py -q
   ```

   Он теперь обязан падать, если у пятнадцати эмитентов из двадцати нет
   непустой `net_margin`. Зелёный — значит на экране появились настоящие

5. **`git log --oneline origin/agent/night-2..agent/night-2`** — если
   непусто, работа не опубликована, см. раздел 0.
6. **Раздел «Disputed»** в отчёте — там места, где агент считает
   задание или скрипт неправыми. За три захода он оказался прав в
   восьми спорах из десяти — читайте этот раздел раньше «Done».

Отчёт и скрипт расходятся — верить скрипту.

## 4. Что отправить рецензенту

Для независимой проверки — своё сообщение. Отдавать можно нескольким
моделям сразу, ответы сравнимы за счёт формата из `agent/REVIEW.md` §8.

```text
Проверь чужой проект как независимый рецензент. Код писали автономные
агенты, их отчёты содержат недостоверные утверждения — верь только тому,

    git clone https://github.com/shemyakin925-ux/RusTerm.git
    cd RusTerm && git checkout agent/night-2
    python3 -m pip install pytest
    cat agent/REVIEW.md

agent/REVIEW.md — бриф проверки: что за проект, что реально сделано,
какие дефекты уже найдены, что смотреть и в каком виде отвечать.
Он самодостаточен, начни с него.

Ничего не чини и не коммить. Твоя задача — найти и описать, а не
исправить. Находка без способа воспроизвести — гипотеза, так её
и помечай.
```

Отправляй **одинаковый** текст каждой модели и сравнивай ответы:
находка, которую увидели двое независимо, почти наверняка настоящая;
одиночная — требует проверки.

восемь блоков покрытия с причинами, — и всё это доступно тестам, но не
человеку. Плюс, даже когда инструмент появится, величины будут пустыми,
потому что SEC называет выручку `us-gaap:Revenues`, а формула ждёт
`revenue`.

Обе дыры — первые пункты ближайшей ночи: V0 (маппинг) и V3 (команда
`add`).

### После этой ночи — то, ради чего она

```bash
rusterm add --ticker AAPL --market US        # новая команда, пункт V3
rusterm watchlist create my --name "Мой список"
rusterm watchlist add my --ticker AAPL --market US
rusterm ingest --watchlist my --source edgar
rusterm snapshot --watchlist my
rusterm tui
```

И `snapshot` выдаёт числа: маржа с указанием года, из которого она посчитана, единицей измерения
и ссылкой на тег SEC, из которого число получено. `rusterm tui`
показывает их в карточке, а по клавише `s` — откуда взято каждое:
документ, локатор, исходный тег и версия маппинга.

Пункты идут по приоритету, поэтому даже короткая ночь оставляет
работающее: V0–V3 не требуют сети вообще и считаются на данных,
которые уже лежат в репозитории. Оборвётся на V4 — у вас всё равно
будут настоящие числа на экране и способ завести свою компанию, просто
набор величин уже, а записанные ответы SEC не перезаписаны шире.

**Интерфейс терминальный, а не оконный** — решение принято в ТЗ-8 U11
и записано в ADR-0009: TUI на `curses` сейчас, десктоп на PySide6
остаётся заявленной целью ADR-0004. Название проекта — RusTerm — этому
не противоречит.
