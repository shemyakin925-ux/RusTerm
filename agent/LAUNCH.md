# Как запустить агента

Актуальное задание — `agent/TASK-3.md` (продолжение с `agent/night-2`).
Оно опирается на `agent/TASK-2.md`, тот остаётся в силе целиком.

Файл для заказчика, не для агента.

---

## 1. Что отправить модели

Текст ниже — для продолжения работы с ветки `agent/night-2`.
Сообщение для запуска с нуля лежит в истории git, коммит `f41ace5`;
оно больше не нужно: половина работы уже сделана и закоммичена.

```text
Ты автономный агент-исполнитель. Работаешь до упора, один, без связи
со мной. Вопросов задавать некому. Обрыв сети, таймаут, исчерпанный
лимит, падение процесса — это пауза, а не конец: правила возобновления
описаны в репозитории, следуй им.

Репозиторий: https://github.com/shemyakin925-ux/RusTerm.git

Выполни это до любых рассуждений и планов:

    git clone https://github.com/shemyakin925-ux/RusTerm.git
    cd RusTerm
    git fetch origin
    git checkout -B agent/night-2 origin/agent/night-2
    cat agent/SKILL.md
    cat agent/TASK-2.md
    cat agent/TASK-3.md
    bash agent/acceptance.sh

Прочитай все три файла целиком, до конца, прежде чем написать первую
строку кода. SKILL.md — способ работы. TASK-2.md — задача и приёмка.
TASK-3.md — где именно остановился предыдущий агент и что делать
дальше; начинай с него.

Работа уже наполовину сделана до тебя и закоммичена. Ничего из неё
не переписывай: пятнадцать инвариантов, пять xfail(strict=True),
gzip-фолбэк и удаление rusterm/cli.py — это готовое. Твоя первая
задача — четыре конкретных дефекта из TASK-3.md §2, они там разобраны
поимённо, с причиной и способом починки.

Пять правил, которые перевешивают любые твои соображения по ходу:

1. Коммить после каждого закрытого пункта, а не в конце. Два агента
   до тебя не потеряли работу только потому, что её подобрали из
   рабочего дерева вручную. Третий раз этого может не случиться.
2. Приёмка — это `bash agent/acceptance.sh`, а не твоя оценка своей
   работы. Править этот файл запрещено, он сверяется с origin/main.
   Считаешь проверку неверной — пиши в раздел «Спорное» отчёта.
3. Статус «сделано» ставится только рядом с фактическим выводом
   команды и её кодом возврата. Без вывода — это гипотеза, и я буду
   считать пункт невыполненным.
4. Падающий тест не ослабляется и не удаляется никогда. Не поддаётся
   после трёх разных попыток — xfail(strict=True, reason=...) и запись
   в отчёт. Это нормальный, принимаемый итог.
5. Существующие миграции неприкосновенны. Меняешь схему — добавляй
   новую миграцию с подъёмом schema_version.

agent/REPORT-2.md не начат — заведи его первым коммитом. Впиши туда
и чужую работу: этап A почти целиком сделан не тобой, присваивать его
нельзя.

Область работы ограничена разделами 3-5 TASK-3.md. Ни строки Qt,
ни LLM-слоя, ни реальных сетевых источников.

Начинай.
```

## 2. Что проверить перед запуском

- **Доступ на запись.** Репозиторий публичный, поэтому `git clone`
  у агента пройдёт без всякого токена — и именно поэтому легко забыть,
  что `git push` токена по-прежнему требует. Прошлый заход оставил всю
  работу И6-И13 незакоммиченной внутри контейнера; не открой я рабочее
  дерево, она бы просто пропала. Выдай токен с правом записи либо впиши
  в сообщение отдельной строкой: «пуш недоступен, утром отдай
  `git bundle --all` файлом».
- **Всё, что агент запушит, станет публичным немедленно.** Отозвать
  опубликованное нельзя: форки и зеркала остаются. Поэтому запрет
  выдумывать данные и требование помечать фикстуры синтетическими
  (TASK-2.md §2, `SKILL.md` §6) теперь не гигиена, а защита от того,
  что придуманное число уедет наружу под видом отчётности эмитента.
- В контейнере есть `python3` версии 3.12 или новее и `git`.
- `pytest` ставится из сети. Не встанет — агент по заданию обязан
  продолжить и записать это; проверка 3 тогда не пройдёт, и это
  честный результат, а не провал.

## 3. Что сделать утром

```bash
cd RusTerm
git fetch origin && git checkout agent/night-2
bash agent/acceptance.sh
```

Дальше по порядку:

1. **Код возврата скрипта.** 0 — принято. Иначе он сам печатает,
   что именно не сошлось.
2. **`git diff origin/main -- agent/acceptance.sh`** — обязан быть
   пустым. Непустой означает, что агент правил приёмку; всё остальное
   после этого можно не читать.
3. **`agent/REPORT-2.md`**, раздел «Чему верить нельзя» — читать первым,
   до раздела «Сделано».
4. **`git log --oneline origin/agent/night-1..agent/night-2`** —
   осмысленная последовательность, история не переписана.
5. **Раздел «Спорное»** в отчёте — там будут места, где агент считает
   задание или скрипт неправыми. Иногда он прав.

Отчёт и скрипт расходятся — верить скрипту.
