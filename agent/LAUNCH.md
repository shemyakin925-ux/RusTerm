причина пропуска теперь называет недостающие концепты по имени
(`missing_data: capex`).

### Что я нашла сверх отчёта: у остатка одна причина

Осталось тринадцать пропусков с причиной «периоды не сошлись» у шести
эмитентов. Я выгрузила по каждому эмитенту последний период каждого
входа, и картина оказалась однотипной:

| эмитент | концепт | его последний период | все остальные входы |
|---|---|---|---|
| AMZN | капвложения | **2016** | 2025 |
| NVDA | капвложения | **2011–2012** | 2025–2026 |
| TSLA | амортизация | **2017** | 2025 |
| BRKB | операционная прибыль | **2012** | 2025 |
| JNJ | операционная прибыль | **2013–2014** | 2025 |

Это не отсутствующие числа. Это **теги, которыми компания перестала
пользоваться**, десять лет лежащие в фиде, — и правило «одна мера, один
период» честно сообщает, что общего периода нет.

Я сходила в живой фид SEC и проверила три случая. Amazon с 2016 года
помечает капвложения другим тегом, Tesla с 2017 — другим тегом
амортизацию; оба новых тега проекту неизвестны. А у Berkshire и J&J
операционной прибыли в XBRL действительно нет и замены не существует.

Отсюда два пункта ночи: словарь узнаёт **два** новых тега, названных
поимённо, и появляется правило, по которому факт десятилетней давности
вообще не годится во входы — тогда Berkshire честно скажет «нет данных
по операционной прибыли» вместо «периоды не сошлись».

Важная деталь, из-за которой я запретила искать теги перебором: поиск
по подстроке `PaymentsToAcquire` выдаёт среди прочего «покупку ценных
бумаг», а это не капвложения. Такой тег дал бы **неверное число** там,
где сейчас честный пропуск. Поэтому в задании ровно две строки таблицы
и прямой запрет добавлять что-либо ещё.

### Спорные пункты: четыре, все разобраны в ТЗ-12 §0.2

1. **Конфликт в моём же тексте про обрезку** — агент нашёл, что моё
   правило «шесть последних периодов» затягивает квартальные и вытесняет
   годовые, и сам предложил разделить на две полосы. Прав; моя
   формулировка была недоопределена.
2. **Две планки в тесте я задала на глазок, и обе завысила.** JPMorgan —
   банк и операционной прибыли в этом смысле не показывает; валовую
   прибыль в принципе раскрывают 7 компаний из 20. Агент планки **не
   понизил**, а вынес недостачу в строгий `xfail` с перечислением
   виноватых эмитентов — это сильнее, чем понизить: как только данные
   улучшатся, тест покраснеет и потребует пересмотра. Ровно правильное
   поведение.
3. **Строки словаря не хватало, и её должна была написать я.** Агент
   отказался править `docs/` (это запрещено проверкой 10) и вместо
   этого завёл временное исключение в тесте-стороже. Строку я дописала,
   исключение снимается первым же делом.
4. **Ключ `current_version` переименован в `version` «попутно».** По
   существу агент прав, ключ оставляю. По способу — нет: имя ключа в
   `--json` это договор с пользователем, и его переименование бывает
   пунктом задания, а не побочным эффектом. С этой ночи правило
   записано в ТЗ.

это перестаёт быть просьбой и становится тестом.

## 1. Что отправить исполнителю

Сначала — **в той же оболочке, из которой запускаете агента**:

```bash
set -a; . ~/.rusterm.env; set +a
printenv RUSTERM_SEC_UA | cut -c1-12   # должно напечатать начало контакта
```

Без контакта половина пункта Y1 (перезагрузка двадцати файлов под новые
теги) пропускается по правилу, и эффект от новых тегов на двадцати
эмитентах будет не измерен. Сам словарь при этом обновится.

```text
Ты автономный агент-исполнитель. Работаешь один, без связи со мной,
вопросов задавать некому. Обрыв сети, таймаут, исчерпанный лимит —
это пауза, а не конец работы.

Репозиторий: https://github.com/shemyakin925-ux/RusTerm.git

Выполни это до любых рассуждений и планов:

    git clone https://github.com/shemyakin925-ux/RusTerm.git
    cd RusTerm
    git checkout agent/night-2
    git merge origin/main
    printenv RUSTERM_SEC_UA | cut -c1-12
    python3 -m pip install pytest
    cat agent/TASK-12.md
    bash agent/acceptance.sh

Мерж обязателен и идёт первым: в main лежит строка словаря
total_equity_incl_nci, без которой пункт Y4 не выполнить.

Предпоследняя команда обязана напечатать начало контакта для SEC.
Напечатала пусто — работай по офлайн-пути и запиши это фактом,
как велит §1.12 N2 задания. Придумывать контакт запрещено.

Последняя команда обязана напечатать «пройдено 13, провалено 0».
Конфликт при мерже возможен ровно один, в agent/LAUNCH.md, — это мой
файл, бери версию из main дословно.

Дальше работай строго по agent/TASK-12.md: раздел 1 (протокол) главнее

Обрати внимание на §0.3 и пункт Y6: всё, с чем ты не согласен, кладётся

agent/REPORT-13.md. Протокол из раздела 1 ТЗ-12 действует и там.
```

## 1a. Две переменные окружения

Обе читаются из окружения и **не коммитятся** — репозиторий публичный.

**1. Контакт для SEC EDGAR.** В `~/.rusterm.env` задан, права `600`.
Ничего делать не нужно, кроме команды из раздела 1. Ночь тратит около
двадцати запросов.

**2. Ключ модели.** В ТЗ-12 и ТЗ-13 его не требует ни один пункт —
веха M5 в эти ночи не входит. Оставляйте как есть.

Ограничения на сеть (ТЗ §1.12): только SEC EDGAR, 5 запросов в секунду,
жёсткий потолок 5000 за ночь с отказом; 403 и 429 — остановка и запись,
без смены User-Agent, прокси и зеркал; скачанное не попадает в git,
кроме обрезанных ответов в `tests/data/edgar/`.

## 2. Что проверить перед запуском

- **Доступ на запись.** Либо токен с правом записи, либо строка в
  сообщении: «пуш недоступен, утром отдай `git bundle create
  ../RusTerm-handoff.bundle --all` файлом».
- **Ветка на GitHub актуальна:** `origin/agent/night-2` = `6246fa1`.
- **Собираетесь закрыть репозиторий — сделайте это до запуска и дайте
  агенту токен.** Сейчас GitHub отдаёт `visibility: public`; после
  закрытия `git clone` в промпте перестанет работать без учётных данных
  и ночь умрёт на первой команде.
- **Всё, что агент запушит, станет публичным немедленно.**
- В контейнере есть `python3` 3.12 или новее и `git`.

## 3. Что сделать утром

```bash
cd RusTerm
git fetch origin && git checkout agent/night-2
git merge origin/main
bash agent/acceptance.sh
```

Дальше по порядку:

1. **Код возврата скрипта.** 0 — принято.
2. **`git diff origin/main -- agent/acceptance.sh`** — обязан быть
   пустым. Непустой означает, что агент правил приёмку; остальное
   можно не читать.
3. **`agent/ACCEPTANCE-10.txt`**, затем `agent/REPORT-12.md`, разделы
   «Disputed», «HANDOFF» и «What not to trust» — до раздела «Done».
4. **Команда, отвечающая на вопрос этой ночи:**

   ```bash
   python3 -m pytest tests/test_m3_snapshot.py -q -s -rx
   ```

   Печатает таблицу «мера → сколько из двадцати». Смотрите на строки
   `operating_margin` и на число причин `period_mismatch`: их должно
   стать меньше тринадцати, а у Berkshire и J&J причина обязана
   смениться на «нет данных по операционной прибыли».
5. **Проверка, что J&J снова не поехал:**

   ```bash
   git diff origin/main -- tests/data/golden_m2.json | grep '^[-+].*expected'
   ```

   Обязана быть пустой.
6. **`git log --oneline origin/agent/night-2..agent/night-2`** — если
   непусто, работа не опубликована.
7. **Раздел «Disputed»** — за пять заходов агент оказался прав в
   шестнадцати спорах из семнадцати. Читайте раньше «Done».

Отчёт и скрипт расходятся — верить скрипту.

## 4. Что отправить рецензенту

Для независимой проверки — своё сообщение. Отдавать можно нескольким
моделям сразу, ответы сравнимы за счёт формата из `agent/REVIEW.md` §8.

```text
Проверь чужой проект как независимый рецензент. Код писали автономные
агенты, их отчёты содержат недостоверные утверждения — верь только тому,
что запустишь сам.

    git clone https://github.com/shemyakin925-ux/RusTerm.git
    cd RusTerm && git checkout agent/night-2
    python3 -m pip install pytest
    cat agent/REVIEW.md

agent/REVIEW.md — бриф проверки: что за проект, что реально сделано,
какие дефекты уже найдены, что смотреть и в каком виде отвечать.
Он самодостаточен, начни с него.

Ничего не чини и не коммить. Твоя задача — найти и описать, а не
исправить. Находка без способа воспроизвести — гипотеза, так её
и помечай.
```

Отправляй **одинаковый** текст каждой модели и сравнивай ответы:
находка, которую увидели двое независимо, почти наверняка настоящая;
одиночная — требует проверки.

## 5. Как запустить программу

### Сегодня это уже работает целиком

```bash
git clone https://github.com/shemyakin925-ux/RusTerm.git
cd RusTerm && git checkout agent/night-2
python3 -m venv .venv && .venv/bin/python -m pip install -e .
set -a; . ~/.rusterm.env; set +a

.venv/bin/rusterm init
.venv/bin/rusterm add --ticker AAPL --market US
.venv/bin/rusterm ingest --ticker AAPL --market US --source edgar
.venv/bin/rusterm snapshot --ticker AAPL --market US
.venv/bin/rusterm tui
```

`add` теперь сам находит и CIK, и название компании — «Apple Inc.», а не
«AAPL». Ровно этот путь проверяется тестом на настоящих подпроцессах,
поэтому он больше не может тихо сломаться.

И `snapshot` выдаёт не одну величину, а восемь-десять: чистая и
операционная маржа, эффективная ставка налога, EBITDA, свободный
денежный поток, покрытие процентов, рентабельность капитала,
оборачиваемость активов — каждая с годом, из которого посчитана, с
единицей измерения и со ссылкой на исходный тег SEC. Пустые называют
причину поимённо: «нет данных: капвложения». В `rusterm tui` по клавише
`s` видно, откуда взято каждое число: документ, локатор, тег и версия
маппинга.

### Что даст эта ночь

Меньше пустых клеток у Amazon, NVIDIA и Tesla — им не хватало ровно
двух тегов. И честные формулировки там, где данных действительно нет:
Berkshire перестанет говорить «периоды не сошлись» про операционную
прибыль, которой у неё в отчётности просто нет.

**Интерфейс терминальный, а не оконный** — решение принято в ТЗ-8 U11
и записано в ADR-0009: TUI на `curses` сейчас, десктоп на PySide6
остаётся заявленной целью ADR-0004.
