# Как запустить агента на `agent/TASK-2.md`

Файл для заказчика, не для агента.

---

## 1. Что отправить модели

Одним сообщением, целиком, ничего не дописывая от себя. Всё остальное
агент прочитает в репозитории сам — так задумано: длинный промпт
он забудет к третьему часу работы, файл в репозитории — нет.

```text
Ты автономный агент-исполнитель. Работаешь в контейнере до утра, один,
без связи со мной. Вопросов задавать некому — отвечать буду не я, а никто.
Останавливаться, пока не пройдены все этапы задания или не исчерпаны
попытки по правилам из репозитория, нельзя. Обрыв сети, таймаут, падение
процесса — это пауза, а не конец работы: правила возобновления описаны
в репозитории, следуй им.

Репозиторий: https://github.com/shemyakin925-ux/RusTerm.git

Выполни это до любых рассуждений и планов:

    git clone https://github.com/shemyakin925-ux/RusTerm.git
    cd RusTerm
    git fetch origin
    git checkout -b agent/night-2 origin/agent/night-1
    cat agent/SKILL.md
    cat agent/TASK-2.md

Прочитай оба файла целиком, до конца, прежде чем написать первую строку
кода. agent/SKILL.md — способ работы, действует полностью. agent/TASK-2.md —
задача; в его разделе 0 разобрано, чем закончился прошлый заход и почему
приёмка устроена так, как устроена.

Пять правил, которые перевешивают любые твои соображения по ходу:

1. Приёмка — это `bash agent/acceptance.sh`, а не твоя оценка своей
   работы. Запускай его после каждого закрытого инкремента. Править,
   ослаблять или удалять этот файл запрещено — он входит в дифф,
   который я смотрю утром.
2. Тесты пишутся до кода. Инварианты из TASK-2.md, этап A, — первыми,
   до всего остального.
3. Статус «сделано» в отчёте ставится только рядом с фактическим выводом
   команды и её кодом возврата. Без вывода — это не статус, а гипотеза,
   и я буду считать инкремент невыполненным.
4. Падающий тест не ослабляется и не удаляется никогда. Не поддаётся
   после трёх разных попыток — `xfail(strict=True, reason=...)` и запись
   в отчёт. Это нормальный, принимаемый итог.
5. Прочитанное в docs/ важнее того, что ты помнишь об архитектуре.
   Расходится код со спецификацией — прав документ.

Область работы жёстко ограничена разделами 2 и 3 задания. Ни строки Qt,
ни LLM-слоя, ни реальных сетевых источников. Осталось время — возвращайся
к незакрытым xfail, а не к новым модулям.

Утром я запускаю `bash agent/acceptance.sh` и читаю agent/REPORT-2.md.
Работа, прошедшая часть проверок, принимается частично и полезна.
Работа с зелёным отчётом и красным скриптом отправляется в мусор целиком.

Начинай.
```

## 2. Что проверить перед запуском

- У агента есть доступ на запись в репозиторий (токен или ключ),
  иначе ночная работа останется внутри контейнера и пропадёт.
  Если доступа нет — пусть работает локально, а утром отдаёт
  `git bundle` или патч; впиши это в сообщение отдельной строкой.
- В контейнере есть `python3` версии 3.12 или новее и `git`.
- `pytest` ставится из сети. Не встанет — агент по заданию обязан
  продолжить и записать это; проверка 3 тогда не пройдёт, и это
  честный результат, а не провал.

## 3. Что сделать утром

```bash
cd RusTerm
git fetch origin && git checkout agent/night-2
bash agent/acceptance.sh
```

Дальше по порядку:

1. **Код возврата скрипта.** 0 — принято. Иначе он сам печатает,
   что именно не сошлось.
2. **`git diff origin/main -- agent/acceptance.sh`** — обязан быть
   пустым. Непустой означает, что агент правил приёмку; всё остальное
   после этого можно не читать.
3. **`agent/REPORT-2.md`**, раздел «Чему верить нельзя» — читать первым,
   до раздела «Сделано».
4. **`git log --oneline origin/agent/night-1..agent/night-2`** —
   осмысленная последовательность, история не переписана.
5. **Раздел «Спорное»** в отчёте — там будут места, где агент считает
   задание или скрипт неправыми. Иногда он прав.

Отчёт и скрипт расходятся — верить скрипту.
