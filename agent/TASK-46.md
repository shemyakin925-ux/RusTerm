## N1. Страж HANDOFF проверяет не тот блок

В `agent/REPORT-45.md` два заголовка:

     49:## HANDOFF
    106:## HANDOFF (FINAL — supersedes the interim values above)

`_sections()` в `tests/test_report_sections.py` ключует секцию по всему
тексту заголовка, поэтому «HANDOFF (FINAL — …)» для стража — **другая
секция, которой нет в `REQUIRED_SECTIONS`**. Проверяется первый,
промежуточный блок со `Status: PARTIAL`; настоящий финальный HANDOFF не
проверяется вовсе — ни на пустоту, ни на шаблонные заполнители. Смена
может закончиться блоком из одних `<...>`, и приёмка этого не увидит.

**Done when:**
- страж проверяет **последнюю** секцию, чей заголовок начинается с
  `HANDOFF` (регистр как есть), и именно её проверяет на пустоту и на
  заполнители `N passed`, `M skipped`, `<`;
- красный случай доказан прогоном: отчёт с промежуточным `## HANDOFF`
  (заполненным) и финальным `## HANDOFF (FINAL)` из одних заполнителей
  краснит тест с внятным сообщением. Временный файл, не твой отчёт;
- зелёный случай: сегодняшний `agent/REPORT-45.md` проходит;
- `REQUIRED_SECTIONS` не ослаблен: отсутствие любой из пяти секций
  по-прежнему красное.

## N2. Экран разговора не открывается — падение по клавише «c»

ТЗ-42 I3 отчиталось «экран разговора готов», приёмка 13/13 это
пропустила. Экран недостижим: в `rusterm/tui/app.py` вызов и объявление
разошлись.

    $ python3 -c "import ast; ..."      # в свежем дереве на addc744
    def _chat_screen params: ['stdscr', 'repos', 'session_id'] line 100
    call at line 47 positional args: 4
    $ ...
    TypeError: _chat_screen() takes 3 positional arguments but 4 were given

Строка 47 — `_chat_screen(stdscr, repos, make_intent_client(), None)`;
объявление на строке 100 берёт три параметра. Клиент там лишний вдвойне:
`_chat_screen` строит его сам через `make_intent_client()` внутри, как
и требует I4. То есть нажатие «c» на экране списка роняет TUI
исключением, и ни один тест этого не ловит — тесты зовут
`_chat_screen` напрямую, минуя клавишу.

Это ровно тот дефект, ради которого заведён `tests/test_single_door.py`:
приёмка проверяет строение, а не связность.

**Done when:**
- нажатие «c» на экране списка открывает разговор; вызов и объявление
  согласованы (клиент строится одной дверью, второй раз не передаётся);
- **тест ведёт экран через клавишу**, а не зовёт функцию напрямую:
  фальшивый `stdscr` отдаёт `ord("c")`, затем `27`, и тест утверждает,
  что разговор открылся и вернулся без исключения. Такой тест обязан
  краснеть на сегодняшнем коде — покажи его красным до правки и зелёным
  после, обе строки в отчёте;
- `tests/test_single_door.py` зелёный без новых исключений и без записи
  в `PENDING`.
