## Где мы

`agent/CONTEXT.md` §4: **US 10 мер из 10, CA 3 из 10, OTC 3 из 10** —
все три канала через EDGAR. Семь мер по Канаде и семь по OTC — отказы.
Почему именно эти семь и что каждой не хватает, не знает никто: цифра

Пока это не разобрано, любое «улучшим покрытие» — угадывание.

## R1. Перепись отказов, а не их устранение

Никакого ремонта в этом пункте. Только измерение.

**Done when:**
- команда даёт таблицу: **эмитент × мера × причина отказа** для одного
  канадского эмитента и одного OTC, десять мер каждый. Причина — токен
  из `rusterm/reasons.py`, не проза;
- для каждой причины названо **конкретное отсутствующее**: какой
  концепт `us-gaap`/`ifrs-full` не нашёлся, или какой факт есть, но
  `verified=no`, или какого периода не хватает. Одна строка на меру;
- таблица воспроизводима офлайн: сохранённые ответы лежат в
  `tests/data/<provider>/`, прогон без сети даёт ту же таблицу;
- результат — в отчёт целиком, все двадцать строк. Это вход для R2 и
  для моего следующего ТЗ.

## R2. Две самые дешёвые меры — починить

Из таблицы R1 возьми **две** меры, которым не хватает меньше всего
(например, концепт есть под другим именем в `ifrs-full`, или период
берётся годовой вместо TTM — `period_basis` уже умеет это показывать,
ТЗ-32 D6).

**Done when:**
- две меры считаются для канадского эмитента из сохранённых фактов;
- у каждой в lineage виден источник и `period_basis`;
- золотой тест на сохранённых данных: мера даёт ровно то число,
  которое ты записал в отчёт;
- остальные восемь по-прежнему дают **честный отказ с причиной** —
  ни одна не начала возвращать выдуманное число. Проверено assert-ом
  на каждую из восьми;
- `agent/CONTEXT.md` §4: строка покрытия обновлена числом, которое дал
  прогон, а не ожиданием.

## R3. Ключ, которого нет

`agent/REPORT-45.md` в секции Secrets говорит: «DART key absent from the
env file». `agent/CONTEXT.md` §5 утверждает обратное — ключи выданы с
13.09.2026, и «нет ключа» не уважительная причина.

Одно из двух неверно. Выясни, какое, **не печатая значений**.

**Done when:** в отчёте названо, какие из четырёх переменных
(`RUSTERM_SEC_UA`, `RUSTERM_DART_KEY`, `RUSTERM_TWELVEDATA_KEY`,
`RUSTERM_LLM_API_KEY`) присутствуют в окружении и какие в файле —
только «есть»/«нет» и длина, значения не печатаются нигде. Если
`RUSTERM_DART_KEY` действительно отсутствует, это **Disputed** для
координатора, а не повод трогать корейский канал.
