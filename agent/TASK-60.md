## E1. P1 судит коммит слияния и блокирует всё (первый по приоритету)

`agent/p1_rule.sh` при пустом `.py`-индексе смотрит `HEAD~1..HEAD`
(правило ТЗ-36 H6.3 — не проходить впустую). Но HEAD сейчас **коммит
слияния**, и `git diff HEAD~1 HEAD` показывает всю работу полос разом,
включая снятые assert-строки, объявления к которым лежат в сообщениях
исходных коммитов, а не в сообщении слияния. Итог: P1 краснеет на уже
принятой работе, и это не косметика —

- любой коммит, в индексе которого нет ни одного `.py` (отчёт,
  `STATE.json`, `BATON.json`, markdown), красный по хуку;
- два стража из таблицы выше красные по этой же причине;
- координатор 21.09.2026 был вынужден положить правку
  `agent/BACKLOG.md` через `--no-verify` — это записано здесь честно,
  а не замолчано.

Правило H6.3 сохраняется: пустой индекс не проходит впустую.

**Done when:**
- фолбэк не судит работу, которую он не может судить: коммит слияния

## E2. Пять причин вне закрытого словаря

`tests/test_b1_reasons.py` называет их поимённо:

| Причина | Где |
|---|---|
| `synthetic_demo_only` | `rusterm/desktop/actions.py:150` |
| `index_unavailable` | `rusterm/desktop/actions.py:192` |
| `fetch_failed` | `rusterm/desktop/actions.py:197` |
| `unexpected_error` | `rusterm/desktop/actions.py:186`, `:213` |
| `no_data_dir` | `rusterm/cli/__init__.py:1599` |

Правило 2 `agent/CONTEXT.md` §3: число либо посчитано, либо отсутствует
с причиной **из `rusterm/reasons.py`**. Пять причин вне словаря — это
пять отказов, которые пользователь видит, а программа не признаёт.

Отдельно: `reason=f"unexpected_error:{e}"` кладёт текст исключения в
**причину**. Продолжение после `:` словарь пропускает по первому
токену, так что формально это пролезет, — но причина перестаёт быть
перечислимой величиной. Текст исключения живёт в `detail`; намерение
комментария «трассировка — не ответ окна» при этом сохраняется.

**Done when:**
- каждая из пяти либо заведена в `rusterm/reasons.py` с комментарием о
  смысле для пользователя, либо заменена существующей — решение по
  каждой названо строкой в отчёте;
- текст исключения из `unexpected_error` перенесён в `detail`; причина
  остаётся голым токеном;
- `python3 -m pytest tests/test_b1_reasons.py` зелёный;
- ни одна existing-причина не переименована ради удобства.
