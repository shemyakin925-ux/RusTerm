## K1. Закоммитить всё

- В каждом дереве этого клона: незакоммиченное, относящееся к
  проекту, — коммитом в `agent/night-11` (код — через ТЗ исполнителю,
  если это код; файлы координатора — самой). Мусор (`dist/`, `build/`,
  `*.bak`, `*.orig`, временные базы) не коммитится, удаляется.
- **Готово, когда:** `git status --porcelain` пуст во всех деревьях,
  которые остаются после K3; `bash agent/acceptance.sh` → 13/0.

## K2. Влить в main всё актуальное

- `main` ← `agent/night-11` **только fast-forward** (`git merge
  --ff-only`, ТЗ-81 B1 это обеспечил); приёмка на голове 13/0 до и
  после; push `main`.
- Для каждой другой ветки: `git cherry -v agent/night-11 <ветка>`.
  Все строки «−» (патчи уже внутри) → ветка в список K3. Есть «+» →
  строка таблицы на коммит: что меняет. Код, которого нет в night-11 и
  который нужен продукту, — cherry-pick отдельным коммитом с приёмкой;
  координационные файлы старых кругов не переносятся; неясное —
  пользователю таблицей, ждать да/нет.
- **Готово, когда:** `git log origin/main..origin/agent/night-11` пуст;
  таблица «ветка → решение» в LAUNCH.

## K3. Удалить ненужные ветки и деревья

- Удаляется ветка, у которой `git cherry` против `main` без «+» (или
  `git branch --merged main`) и которая не открыта ни в одном живом
  дереве. **Никогда:** `main`, рабочая ветка эстафеты `agent/night-11`,
  ветка с «+» без решения пользователя, ветка текущего дерева
  пользователя без его «да».
- Дерево удаляется `git worktree remove` (без `--force`), только если
  в нём чисто и в нём никто не работает (`lsof +D <путь>` пуст); иначе
  пропуск с причиной в таблице. Затем `git worktree prune`.
- Удалённые ветки — `git push origin --delete` по таблице, после «да»
  пользователя (удаляет у всех клонов).
- **Готово, когда:** `git branch -a` — только оставленное, каждая
  оставшаяся ветка названа с причиной.

## K4. Убрать бесполезную информацию

Файл из `agent/` удаляется, если **все** условия:
1. его ТЗ закрыто (принято или заменено), и оно старше пяти последних
   принятых ТЗ;
2. ни один отслеживаемый файл на него не ссылается — grep имени по
   `tests/`, `rusterm/`, `agent/*.py`, `agent/*.sh`, `agent/CONTEXT.md`,
   `agent/PROTOCOL.md`, `agent/BACKLOG.md`, `README.md`, `GUIDE.md`,
   `AGENTS.md`, `CLAUDE.md`;
3. приёмка после удаления — 13/0 (иначе файл возвращается).

`docs/` не трогается (приёмка, пункт 10); `acceptance.sh`, стражи,
`relay.py`, `BATON.json`, `STATE.json`, открытые ТЗ и их отчёты
остаются. Правило пользователя «старые ТЗ не переписываются» не
нарушается: файлы не правятся, а убираются из дерева — история git
хранит всё. Одно удаление — один коммит «Координатор: уборка agent/ …»
со списком файлов.
