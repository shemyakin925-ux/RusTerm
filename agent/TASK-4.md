## 1. КАК РАБОТАТЬ. Читай этот раздел целиком, он главный

### 1.1. Цикл. Один пункт задачи — один проход

```

2. ПОКАЖИ     текущее состояние командой и посмотри на вывод.
3. ИЗМЕНИ     ровно один пункт. Не два.
4. ПРОВЕРЬ    командой из строки «Готово, когда» этого пункта.

6. ЗАКОММИТЬ  немедленно, до перехода к следующему пункту.
7. ЗАПИШИ     строку в agent/REPORT-3.md: команда + её вывод.
```

### 1.2. Пять запретов

**З1. Не удаляй `assert`.** Никогда, ни под каким предлогом. Тест,
мешающий изменению, — это сигнал, что изменение неверно, а не что тест
лишний. Если утверждение действительно устарело, его **заменяют более
сильным**, и в отчёте пишут, чем новое строже старого.

Прошлый агент удалил три утверждения, добавил одно и назвал это
усилением. Так делать нельзя.

**З2. Не правь существующие миграции.** Список `_MIGRATIONS`
в `rusterm/store/db.py` — это история, уже применённая на чужих базах.
Правка задним числом до них не доедет: `apply_migrations` пропустит
версию, потому что она уже записана в `schema_version`. Изменение схемы —
всегда **новая** миграция с новым номером.

**З3. Не оставляй файлов вне git.** Всё, о чём ты пишешь в отчёте,
обязано быть в `git ls-files`. Прошлый агент написал ADR, отчитался
о нём и не добавил файл в индекс — работа существовала только у него
на диске.

**З4. Не оставляй `.bak`, `.orig`, временных баз и мусора.** Правишь
файл — правь файл, копии не нужны, для этого есть git.

**З5. Не заявляй о проверке, которой не было.** «Не запускал» —
допустимый ответ. «Работает» без вывода команды — нет.

### 1.4. Когда застрял

Одно и то же не выходит после **трёх разных попыток** — не четвёртой
попытки, а трёх разных гипотез о причине:

1. Останови работу над этим местом.
2. Если это тест — пометь `@pytest.mark.xfail(strict=True, reason="…")`.
   Не удаляй и не ослабляй.
3. Запиши в отчёт: что не вышло, какие три гипотезы проверил.
4. Переходи к следующему пункту.

Это нормальный, принимаемый итог. Заблокированный пункт с честным
объяснением полезнее закрытого обманом.

## 2. Задачи

### T1. Миграция 33 вместо правки существующей

**Что не так.** Прошлый агент изменил `CHECK (compression IN
('none','zstd'))` на `('none','zstd','gzip')` прямо в миграции, которая
уже применена. Проверено: на базе, созданной прежней версией,
`apply_migrations` применяет 0 миграций, `schema_version` остаётся 32,
старое ограничение остаётся на месте, запись gzip-объекта падает с
`IntegrityError: CHECK constraint failed`. Тесты этого не видят, потому
что каждый создаёт базу с нуля.

**Шаг 1. Верни миграцию как было.** В `rusterm/store/db.py`, в записи
списка `_MIGRATIONS` с таблицей `raw_object`:

```
compression TEXT NOT NULL CHECK (compression IN ('none','zstd')),
```

**Шаг 2. Научи движок многооператорным миграциям.** Сейчас
`apply_migrations` выполняет каждую миграцию через `conn.execute(sql)`,
а он умеет ровно один SQL-оператор и на нескольких бросает
`ProgrammingError`. Пересборка таблицы — это четыре оператора.

Добавь в цикл ветку: если в SQL больше одного оператора — выполняй его
через `conn.executescript(sql)`, иначе оставь `conn.execute(sql)` как
есть. Поведение существующих 32 миграций измениться не должно.

**Шаг 3. Добавь миграцию 33** в конец `_MIGRATIONS` и подними
`_SCHEMA_VERSION` до 33. SQLite не умеет менять `CHECK` через `ALTER`,
поэтому таблица пересобирается:

```sql
PRAGMA foreign_keys=OFF;
CREATE TABLE raw_object_new (
    sha256 TEXT PRIMARY KEY,
    provider TEXT NOT NULL,
    url TEXT,
    fetched_at REAL NOT NULL,
    bytes INTEGER NOT NULL,
    content_type TEXT NOT NULL,
    compression TEXT NOT NULL CHECK (compression IN ('none','zstd','gzip')),
    instrument_id TEXT,
    block TEXT,
    http_status INTEGER,
    etag TEXT);
INSERT INTO raw_object_new SELECT * FROM raw_object;
DROP TABLE raw_object;
ALTER TABLE raw_object_new RENAME TO raw_object;
PRAGMA foreign_keys=ON;
```

`PRAGMA foreign_keys=OFF` обязателен: на `raw_object(sha256)` ссылается
`fact.source_ref`, и без этого `DROP TABLE` уронит связи.

Комментарий у `_SCHEMA_VERSION` сейчас говорит «количество таблиц» —
это перестанет быть правдой, поправь его на «количество миграций».

**Готово, когда** эта команда печатает `applied=[33]`, `version=33`
и `запись gzip: ok`:

```bash
python3 - <<'EOF'
import sqlite3, sys, tempfile, pathlib
sys.path.insert(0, ".")
from rusterm.store import db as m
p = pathlib.Path(tempfile.mkdtemp()) / "old.db"
c = sqlite3.connect(str(p), isolation_level=None)
# база по схеме 32: старый CHECK, миграции 1..32
old = [(s.replace("'none','zstd','gzip'", "'none','zstd'"), n) for s, n in m._MIGRATIONS[:32]]
saved, m._MIGRATIONS, sv = m._MIGRATIONS, old, m._SCHEMA_VERSION
m._SCHEMA_VERSION = 32
m.apply_migrations(c)
m._MIGRATIONS, m._SCHEMA_VERSION = saved, sv
c.execute("INSERT INTO raw_object(sha256,provider,fetched_at,bytes,content_type,compression)"
          " VALUES ('a'*64,'t',0,1,'text/plain','none')")
applied = m.apply_migrations(c)              # «обновление приложения»
print("applied=", applied)
print("version=", c.execute("SELECT MAX(version) FROM schema_version").fetchone()[0])
print("строк уцелело:", c.execute("SELECT COUNT(*) FROM raw_object").fetchone()[0])
try:
    c.execute("INSERT INTO raw_object(sha256,provider,fetched_at,bytes,content_type,compression)"
              " VALUES ('b'*64,'t',0,1,'text/plain','gzip')")
    print("запись gzip: ok")
except Exception as e:
    print("запись gzip:", type(e).__name__, e)
EOF
```

Строка «строк уцелело: 1» обязательна: миграция, потерявшая данные,
хуже несделанной.
