# Бриф для независимой проверки

Файл для стороннего рецензента — человека или модели. Самодостаточен:
чтобы вынести суждение, достаточно этого файла и репозитория.

Ветка для проверки: **`agent/night-2`**.

---

## 1. Предупреждение, с которого надо начать

В репозитории лежат два отчёта агентов-исполнителей, и **оба содержат
недостоверные утверждения**:

- `agent/REPORT.md` заявляет девять закрытых инкрементов и «74 passed».
  Фактически: четыре модуля не импортировались вовсе, тестов на них
  не существовало, прогон давал 69 passed / 5 failed.
- `agent/REPORT-2.md` заявляет «A4 ADR-0007 создан» — файл при этом
  не был добавлен в git; и «Спорное: ни одно» при трёх неверно
  сделанных пунктах из четырёх.

Они оставлены в репозитории намеренно, как след работы. **Не опирайся
на них ни в одном выводе.** Верь только тому, что сам запустил.

То же относится к сообщениям коммитов: `58bf8c3` перечисляет A4 среди
сделанного, хотя файл в этом коммите отсутствует.

## 2. Что это за проект

Десктопное приложение для частного инвестора: по тикеру собирается
research-снапшот (цены, фундаментал, ownership, корпоративные действия,
отраслевые метрики), каждое число кликабельно до первоисточника.
Рынки US/UK/CA, локальное хранилище, без облака.

Спецификация — `README.md` и `docs/`, **21 файл, и это источник истины**:
при расхождении кода и документа прав документ. Ключевое:

| Файл | О чём |
|---|---|
| `docs/data-model.md` | таблицы, факты, снапшоты, peer set |
| `docs/module-contracts.md` | границы слоёв и протоколы |
| `docs/processes.md` | конвейер сбора, сборка снапшота |
| `docs/data-dictionary.md` | концепты и формулы |
| `docs/adr/000*.md` | принятые решения, семь штук |

## 4. Как всё запустить

**Нужен Python 3.12 или новее** — `pyproject.toml` объявляет
`requires-python = ">=3.12"`. На 3.10 и 3.11 не импортируется
`rusterm/store/config.py`: он использует `tomllib`, появившийся
в стандартной библиотеке в 3.11. Это не дефект, а заявленная база;
добавлять фолбэк на пакет `tomli` нельзя — сторонние зависимости
сверх `pytest` запрещены.

Сторонние плагины `pytest` проекту не нужны ни одного. Если в твоём
окружении стоит, например, `pytest-qt`, он потянет `PyQt5` и уронит
прогон — это тоже не дефект репозитория. `agent/acceptance.sh`
запускает тесты с `PYTEST_DISABLE_PLUGIN_AUTOLOAD=1` именно поэтому;
если запускаешь `pytest` руками, делай так же.

```bash
git clone https://github.com/shemyakin925-ux/RusTerm.git
cd RusTerm && git checkout agent/night-2
python3 -m pip install pytest          # больше ничего не нужно
python3 -m pytest -q                   # ожидается 84 passed, 5 xfailed
bash agent/acceptance.sh               # 13 машинных проверок
```

`agent/acceptance.sh` — приёмочный скрипт, он же описывает, что вообще
считается приемлемым: импортируемость всех модулей, наличие инвариантов,
прогон без `zstandard`, границы слоёв, отсутствие заглушек и мусора.
Читается за пять минут и объясняет устройство проекта лучше отчётов.

## 5. Дефекты, уже найденные

Перечислены, чтобы ты не тратил на них время. Найти сверх этого списка —
и есть смысл проверки.

**Д1. Изменение схемы не доезжает до существующих баз.** В миграцию,
уже применённую на чужих базах, внесена правка задним числом
(`CHECK compression IN ('none','zstd')` → добавлен `'gzip'`). На базе,
созданной прежней версией, `apply_migrations` применяет 0 миграций,
`schema_version` остаётся 32, ограничение остаётся старым, запись
gzip-объекта падает с `IntegrityError`. Тесты этого не видят: каждый
создаёт базу с нуля. Ни один из 15 инвариантов такую ситуацию
не проверяет.

**Д2. В `tests/test_raw_store.py` удалены три утверждения** при правке,
поданной как усиление: `assert not plain.exists()`, проверка метки
сжатия во втором тесте, и `exists_zst`/`exists_gz` вычисляются, но
ни во что не входят — комментарий обещает проверку, которой нет.

**Д3. Мусор вне git**: `*.bak`, `*.orig`, пустой
`rusterm/store/test_schema.db`.

**Д4. `docs/adr/0007`** описывает решение, которого не должно быть
(правку миграции на месте), и цитирует несуществующее место
в `agent/TASK-3.md`.

**Д5. `effective_tax_rate` считает ставку при убытке.** Docstring
требует «при `pretax_income <= 0` — ставка юрисдикции», код проверяет
только `== 0` и `None`. Проверено:

```
effective_tax_rate(tax=-100, pretax=-1000) = (0.1, None)
effective_tax_rate(tax= 100, pretax=-1000) = (0.0, None)
```

Второй случай опаснее: `clip(…, 0, 0.5)` даёт ровно `0.0`, и нулевая
ставка выглядит правдоподобно. Ставка идёт в NOPAT, NOPAT — в ROIC.

**Д6. `calculate_measure("invested_capital")` бросает исключение
на неполных данных.** Ветка допускает вызов при заполненных
`total_equity`, `minority_interest`, `total_debt`, а сама
`invested_capital` требует пять обязательных аргументов. Проверено:

```
calculate_measure("invested_capital", total_equity=100, minority_interest=0, total_debt=50)
  -> TypeError: missing 2 required positional arguments: 'cash' and 'st_investments'
```

Контракт движка (`docs/module-contracts.md`) требует null с причиной,
а не исключение. Отсутствие cash в отчётности — обычное дело.

**Д7. EBITDA равна operating income, если D&A не раскрыта.** При
`operating_income is not None` и `d_and_a is None` значение остаётся
равным operating income, `null_reason` пустой. Проверено:

```
calculate_measure("ebitda", operating_income=100, d_and_a=None)
  -> Measure(value=100, null_reason=None, lineage=[])
```

Два дефекта в одном: молчаливо неверная EBITDA (база для EV/EBITDA
и net debt / EBITDA) и непустое `value` при пустом `lineage`, что
запрещено инвариантом I4 — тот сейчас `xfail` и потому не ловит.

**Д8. Маржи принимают отрицательный знаменатель.** `gross_margin`,
`operating_margin`, `net_margin` проверяют `revenue == 0`, тогда как
data dictionary требует null при знаменателе `<= 0`. Проверено:

```
gross_margin(gross_profit=10, revenue=-100) = (-0.1, None)
roic(10, -50, -50)                          = (None, 'negative_denominator')
```

Вторая строка — соседняя функция того же модуля, обрабатывающая
тот же случай правильно.

Д5-Д8 найдены сторонним рецензентом и **перепроверены владельцем
запуском на реальном коде** — приведённые выводы фактические.
Точечно чинить `formulas.py` не планируется: модуль целиком
переписывается в инкременте И9 с golden-file, и Д5-Д8 входят в его
приёмочные критерии.

**Д9. Пять инвариантов из пятнадцати — пустышки.** Тело I4, I5, I6,
I13 и I15 состоит из одного `pytest.fail(...)`, проверок нет ни одной.
Хуже: `xfail(strict=True)` не снимет их автоматически при появлении
кода, потому что `pytest.fail` падает всегда. I15 показателен — правило
знаменателя `formulas.py` уже реализует (`roic(10,-1,-1)` →
`(None, 'negative_denominator')`), а тест молчит.

**Д10. `Fact` изменяем, хотя объявлен неизменяемым.** Шесть локаторов —
`@dataclass(frozen=True)`, сам `Fact` (строка 120) — обычный
`@dataclass`. `f.value = "2"` проходит. Инвариант I2 этого не ловит:
он проверяет текст `repos.py` через `inspect.getsource`, а не поведение.

Д5-Д10 перепроверены владельцем запуском на реальном коде —
приведённые выводы фактические. Ещё пять дефектов, требующих проектного
решения, вынесены в `agent/BACKLOG.md`: отсутствие резервной копии перед
миграцией, неатомарная запись в store, сироты в `RawRepo.put`, движок
миграций без эволюции схемы и сверки checksum, отсутствие фабрики
соединения с обязательными PRAGMA.

Задание на устранение — `agent/TASK-5.md`, отложенное — `agent/BACKLOG.md`.

## 6. Что проверить

По убыванию ценности:

1. **Архитектурные дыры**, которых не закрывает ни один из 15
   инвариантов. Д1 — пример такой дыры, найденной поздно. Есть ли
   другие: границы слоёв, идемпотентность, конкурентная запись,
   целостность после сбоя на середине.
2. **Расхождения кода со спецификацией** `docs/`. Документ прав,
   код исправляется — если найдёшь расхождение, укажи файл и раздел.
3. **Тесты, проверяющие код против самого себя**, а не против
   требования. Их легко узнать: тест переписывали после того, как
   он упал.
4. **`formulas.py` смотрели, четыре дефекта уже найдены (Д5-Д8).**
   Модуль без единого теста, так что находки там дёшевы и, скорее
   всего, не исчерпаны — но повторять Д5-Д8 не надо.
5. **Спецификация сама по себе**: `docs/` проходил два аудита, но
   код по нему почти не написан, и часть решений может оказаться
   невыполнимой на практике.
6. **Приёмочный скрипт**: что он пропускает. В нём уже нашлись
   две ошибки, дававшие ложные провалы.

## 7. Чего проверять не надо

Интерфейса нет — Qt в проекте запрещён на этом этапе. LLM-слоя,
Industry View, провайдеров UK/CA, реальных сетевых источников нет
и не должно быть. Заглушки в `rusterm/providers/` и `rusterm/parsers/` —
известная незаконченность, а не дефект; это следующий этап работы.

Производительность, стиль оформления и покрытие ради покрытия
не интересуют.

## 8. Формат ответа

Чтобы можно было сравнить несколько независимых проверок между собой:

```
## Находки
Для каждой: файл и строка · что не так · как воспроизвести ·
почему это важно · насколько уверен (высокая/средняя/низкая).

## Проверено и претензий нет
Перечисли, что смотрел и счёл здоровым. Это не менее ценно:
показывает охват.

## Не проверял
Честно: что не смотрел и почему.
```

Находка без способа воспроизвести — гипотеза, так её и помечай.
