## T1. Разговор: клиент двери умеет то, что зовёт сессия

`rusterm/core/chat.py:137` зовёт `self._client.chat(prompt, history)`.
`make_intent_client` (`rusterm/core/llm.py`) отдаёт `LlmApiClient` или
`RuleClient` — **ни у одного нет метода `chat`**. Единственная
реализация протокола — локальный класс `_Adapter` внутри `cmd_chat`
(`rusterm/cli/__init__.py`), экрану недоступный. Итог: «c», вопрос,
Enter — `AttributeError`, весь интерфейс падает с кодом 2. И с ключом,
и без.

Тесты это пропустили, потому что подменяли дверь фальшивкой с методом
`chat`, а соседний тест сверял **текст исходника** на подстроку
`make_intent_client`.

**Done when:**
- дверь разговора (например `make_chat_client`) живёт в
  `rusterm/core/llm.py`, отдаёт клиента с `chat(prompt, history) ->
  {text, tool_calls, error}`; её зовут и CLI, и экран;
- клиента модели нет — дверь отдаёт клиента, который отвечает
  **названной причиной значением**, а не падает и не молчит;
- тест ведёт настоящую дверь через `ChatSession.ask` и краснеет, если у
  клиента нет `chat`. Подмена двери фальшивкой в этом тесте запрещена.

## T3. `ops` с заданным ключом не работает ни у кого

`rusterm/core/llm.py` строит `LlmApiClient.from_env(environ=env)` **без
гейта**, а `complete()` без гейта сразу отдаёт
`ConfigError("llm_provider_requires_gate")`. `classify`
(`rusterm/core/intent.py`) делает `str()` от ошибки-значения, получает
не-JSON и печатает «ответ модели не JSON», потратив на это ещё один
вызов модели. Без ключа тот же запрос отрабатывает правилом и печатает
план — то есть **с ключом продукт хуже, чем без**. Воспроизведение за
0,12 с, сеть не нужна:

```bash
python3 -m rusterm.cli --root <каталог> ops --watchlist <список> --request "добавь AAPL"
```

**Done when:**
- дверь намерений строит клиента с гейтом (у `RequestGate` есть точка
  инъекции для теста);
- `classify` отличает ошибку-значение от текста модели, отдаёт
  `Clarification` с настоящей причиной и **не делает повтора**;
- тест с ключом в окружении и стаб-гейтом доводит `ops` до `dry-run`, и
  второй тест закрепляет: на ошибке клиента вызовов ровно один.
