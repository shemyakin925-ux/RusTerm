## Решения

- Миграция 33 как процедурная перестройка raw_object (CHECK +gzip) — существующие
  миграции 1–32 неприкосновенны (I11); runner расширен реестром `_CUSTOM_MIGRATIONS`.
- При P3-коммите `git add -A` затянул появившиеся AGENTS.md/CLAUDE.md (файлы
  координатора, возникшие во время работы). Мой коммит ещё не был опубликован —
  пересобрал его без них (reset --soft по собственному свежему коммиту).
- `ev_ebitda` реализован сверх перечня P4, т.к. входит в раздел «Оценка»
  новой редакции словаря, на который ТЗ ссылается как на источник.
- Парсеры возвращают словари факта (data-model §3), а не core.Fact: сборка Fact —
  обязанность конвейера; при этом правило basis (I3) одно, импортируется из core.
- Пороговые функции peer set живут в core/peers.py; порог 5 для перцентиля
  дублируется проверкой в сборщике снапшота.
- coverage не имеет статуса «частично» (CHECK схемы): проблема передаётся
  через reason (`suspect:N`, `unparsed:N`).
- Prune (`facts_only`) убирает только запись индекса; файл и манифест остаются —
  манифест ведущий (data-model §2).
