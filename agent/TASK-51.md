# TASK-51 — чужая база: обновление без потери данных

- **Status: READY**
- **Report:** `agent/REPORT-51.md`
- **Protocol:** `agent/PROTOCOL.md` (§12). Состояние: `agent/CONTEXT.md`.
- **Relay:** сдать — `python3 agent/relay.py hand --to coordinator
  --report agent/REPORT-51.md --note "<одна строка>"`; затем
  `python3 agent/relay.py status --assert-holder coordinator`; затем
  `python3 agent/relay.py wait --for executor --timeout 3600`.
- **Stop time:** PROTOCOL §10.
- **Budgets:** network 0; model 0.
- **Goal in one sentence:** база пользователя, заведённая старой
  версией, переживает обновление — и это доказано прогоном, а не
  надеждой.

Берётся после ТЗ-50.

## Откуда это задание

Полная проверка 17.09.2026 прошла весь продукт руками и в разделе «что
НЕ проверялось» записала: **путь «пустой каталог → схема 45»**. Ни
одного прогона на базе, созданной прежней версией, не делалось никогда.

Между тем `_SCHEMA_VERSION` дошёл до 45, миграций 44, и у пользователя
на диске лежит SQLite, заведённый месяц назад. Правило проекта —
применённая миграция не переписывается (`agent/CONTEXT.md` §3), но
правило не проверено ни одним тестом на настоящей старой базе.

Дефект здесь тихий: миграция «почти сработала», и часть фактов молча
исчезла. Пользователь узнает об этом, когда мера станет пустой.

## U1. Старая база, собранная настоящим старым кодом

Не эмулируй старую схему руками — возьми её у истории.

```bash
git worktree add --detach /tmp/old-<коммит> <коммит>
```

Возьми **три** точки: схему 41 (`_SCHEMA_VERSION = 41`, есть на
`origin/main`), схему 44 и одну промежуточную по своему выбору. В
каждой: `init`, `demo`, `ingest --instrument US-CLI-DEMO`, `snapshot`,
список наблюдения с двумя версиями. Это и есть «база пользователя».

**Done when:** в отчёте названы три коммита, три номера схемы и по
каждой базе — число строк в ключевых таблицах (факты, снапшоты, меры,
версии списка), снятое **до** обновления.

## U2. Обновление не теряет ничего

Прогони по каждой старой базе сегодняшний код: `doctor`, затем
`status`, `coverage`, `export --format json`.

**Done when:**
- `doctor` доводит базу до 45 и говорит, сколько миграций применил;
- числа из U1 совпадают строка в строку: ни один факт, снапшот, мера
  или версия списка не исчезли и не удвоились;
- `export` со старой базы даёт те же значения мер, что и до
  обновления, — сравнение по файлу, а не на глаз;
- всё это — **тест**, а не ручной прогон: `tests/test_upgrade_path.py`
  строит старую базу из фикстуры, применяет миграции и утверждает
  сохранность. Фикстура — маленькая база в `tests/data/`, положенная в
  git, а не собираемая из сети.

## U3. Обратный ход честен

Пользователь откатился на прежнюю версию с новой базой.

**Done when:** старый код на базе схемы 45 отказывает **названной
причиной** («схема новее, чем знает эта версия»), а не падает
трассировкой и не портит файл. Если сегодня он падает — это находка
ТЗ, не повод чинить старый код: опиши поведение в отчёте и предложи
защиту на будущее (запись версии в заголовок базы, проверка при
открытии).

## U4. Резервная копия переживает обновление

`backup` снимает архив со схемой в манифесте (ТЗ-22 J4).

**Done when:** архив, снятый старой версией, разворачивается новой
(`restore --force`), после чего `doctor` доводит схему до 45 и числа
U1 сходятся; и наоборот — архив новой версии в старую **не**
разворачивается молча, а отказывается по имени.
