# Контракты модулей

Границы между слоями и что через них проходит. Описание, не реализация:
сигнатуры фиксируются на Фазе 1 по этому документу.

Слои — README §10. Зависимости строго вниз: `app → core → normalize →
store`, `sources → store`. Обратных нет ни одной.

---

## 1. Жёсткие запреты границ

| Запрет | Почему |
|---|---|
| `core` не импортирует Qt | иначе ядро не прогнать в тестах и в CLI (ADR-0004) |
| `app` ничего не вычисляет | число на экране обязано совпадать с числом в экспорте |
| `sources` не пишет в базу и не считает метрик | сбор должен быть заменяем и запускаем отдельно (ADR-0003) |
| парсер не ходит в сеть | иначе парсинг не воспроизводится на сохранённом сырье |
| `normalize` не знает имён провайдеров | иначе добавление рынка потребует правок выше |
| LLM не получает инструментов, меняющих состояние | всё через подтверждение пользователя |

Проверка первого и последнего запретов — тестом на импорты, а не ревью.

## 2. MarketDataProvider

Котировки, профиль, классификация, состав индексов.

| Операция | Вход | Выход | Инварианты |
|---|---|---|---|
| `resolve` | тикер, рынок, дата | `instrument_id` либо `ambiguous` со списком, либо `not_found` | разрешение без даты запрещено (ADR-0005); молчаливый выбор первого совпадения запрещён |
| `profile` | `instrument_id` | сырой объект + метаданные | не возвращает факты, только сырьё для парсера |
| `prices` | `listing_id`, диапазон дат | сырой объект | обязан отдавать и `close`, и `adjusted`; только `adjusted` недостаточно, diff строится по `close` |
| `industry_members` | отрасль, фильтры | список кандидатов с тикерами | результат — кандидаты, не члены peer set |
| `index_members` | индекс либо ETF | список кандидатов | то же |

Общие требования к реализации: собственный лимитер запросов; идентификация
клиента там, где источник этого требует; возврат `not_modified` при наличии
валидатора кеша; ни одна операция не бросает исключение наружу — ошибка
возвращается значением.

## 3. DisclosuresProvider

Раскрытия: отчётность, корпоративные действия, сделки инсайдеров,
документы к собранию акционеров.

| Операция | Вход | Выход | Инварианты |
|---|---|---|---|
| `poll_index` | курсор источника | список записей о новых раскрытиях, новый курсор | **один запрос на источник, не на компанию** — на этом держится инкрементальность |
| `list_documents` | `issuer_id`, тип, период | перечень документов с URL и метаданными | без скачивания тел |
| `fetch_document` | URL | сырой объект | идемпотентно: тот же документ даёт тот же `sha256` |

Реализация обязана уметь `poll_index`. Провайдер без индекса изменений
вынуждает полный обход и при 500 бумагах к интеграции не принимается.

## 4. Parser

| Операция | Вход | Выход | Инварианты |
|---|---|---|---|
| `can_parse` | метаданные сырого объекта | да / нет | по типу и источнику, без чтения тела целиком |
| `parse` | сырой объект, контекст эмитента | список фактов, счётчик неразобранного | каждый факт с локатором и `basis`; сети нет; недоразобранное считается и возвращается, а не игнорируется |

Парсер, умеющий вернуть значение, но не умеющий сказать откуда,
к интеграции не принимается (ADR-0001).

## 5. Репозитории (`store`)

Единственный слой, знающий SQL. Прикладной код к базе напрямую не ходит —
иначе смена движка перестаёт быть возможной (ADR-0003).

| Репозиторий | Обязанности | Инварианты |
|---|---|---|
| `InstrumentRepo` | справочники, история тикеров, разрешение по дате | не создаёт инструмент молча при неизвестном тикере |
| `RawRepo` | запись в content-addressed store, манифест, индекс | запись сначала в файл и манифест, потом в индекс; при существующем `sha256` — no-op |
| `FactRepo` | запись и выборка фактов | только вставка; исправление — новый факт плюс `superseded_by` |
| `SnapshotRepo` | версии снапшотов, блоки, measure, lineage | `measure` без lineage не пишется |
| `PeerSetRepo` | версии наборов и состав | версия неизменяема |
| `WatchlistRepo` | версии списков, групп, фильтров | изменение — новая версия целиком |
| `JobRepo` | очередь, попытки, отложенные | постановка идемпотентна по ключу |
| `AuditRepo` | журнал операций | только добавление, дублирование в файл |

Транзакция открывается на уровне процесса, а не репозитория: массовая
операция над watchlist — одна транзакция на всю операцию.

## 6. Core

| Модуль | Обязанности | Не делает |
|---|---|---|
| `metrics` | формулы из data dictionary, `method_version` | не ходит в базу, работает на переданных фактах |
| `peers` | версии наборов, статус, дрейф | не классифицирует сам, принимает предложения |
| `governance` | пороги, цвета, причины | не сворачивает в балл |
| `industry` | агрегаты, концентрация, цикл | не заводит свою классификацию |
| `snapshot` | сборка версии, три вида diff | не рендерит |
| `watchlist` | версии, откат, покрытие | не запускает сбор напрямую, ставит задания |
| `llm` | контекст, вызов, разбор, проверка | не пишет данные без подтверждения |
| `export` | CSV, Excel, JSON | не пересчитывает, берёт готовые measure |

## 7. Модель ошибок

Три класса, разная судьба:

| Класс | Примеры | Кто обрабатывает |
|---|---|---|
| Внешняя | источник недоступен, лимит, таймаут, изменившийся формат | процесс сбора: повтор, отложенная очередь, `coverage=error` с причиной |
| Данных | не сошлась валидация, локатор не разрешается, знаменатель ≤ 0 | помечается `suspect` или даёт `null` с причиной; в расчёт не идёт, из виду не пропадает |
| Программная | нарушен инвариант, несогласованное состояние | падает громко, транзакция откатывается; глушить запрещено |

Общее правило: **внешняя ошибка не должна выглядеть как отсутствие данных.**
Пустой блок и блок со статусом `error` — разные вещи, и пользователь
видит какая именно.
