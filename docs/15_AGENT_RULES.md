# Agent Rules (для LLM-разработчиков)

## ⚠️ КРИТИЧНО ВАЖНО

Этот документ содержит обязательные правила для всех LLM-агентов, работающих над проектом.

**НЕВЫПОЛНЕНИЕ этих правил ведёт к отклонению Pull Request и блокировке задачи.**

---

## 1. Основное Правило: Одна LLM = Одна Задача

**Правило:** Каждая LLM выполняет строго ОДНУ атомарную задачу / одну фазу.

**Обоснование:** 
- Гарантирует проверяемость результата
- Позволяет разным LLM контролировать друг друга
- Предотвращает "раздувание" задач

**Что делать:**
1. Взять задачу из `16_NEXT_TASK.md`
2. Выполнить ТОЛЬКО эту задачу
3. НЕ начинать следующую задачу самостоятельно
4. Оставить репозиторий готовым к проверке

---

## 2. Обязательные Документы для Чтения

**Перед началом ЛЮБОЙ работы LLM ОБЯЗАНА прочитать:**

## 3. Абсолютные Запреты

### 3.1 Запрет на Платные Источники Данных

❌ **КАТЕГОРИЧЕСКИ ЗАПРЕЩЕНО** добавлять платные источники данных:
- Bloomberg Terminal
- Reuters Eikon
- FactSet
- Morningstar Direct
- Любые платные API

✅ **Разрешены ТОЛЬКО бесплатные источники:**
- MOEX ISS
- E-disclosure.ru
- RFSD (rfcd.ru)
- Сайты эмитентов
- ЦБ РФ (cbr.ru)
- Росстат

**Проверка:** Следующая LLM проверит код на наличие платных API ключей.

---

### 3.2 Запрет на Архитектуру «на Вырост»

❌ **ЗАПРЕЩЕНО** добавлять функциональность сверх текущей фазы.

**Пример нарушения:**
- Сейчас фаза 0.2 (Project Skeleton)
- Вы добавляете реализацию MOEX ISS client (это фаза 1.1)
- ❌ Это нарушение!

✅ **Делайте ТОЛЬКО то, что требуется для текущей фазы.**

**Обоснование:**
- Усложняет проверку
- Может конфликтовать с планами на будущие фазы
- Нарушает принцип поэтапной разработки

---

### 3.3 Запрет на Отклонения от Архитектуры

❌ **ЗАПРЕЩЕНО** отклоняться от утверждённой архитектуры (`03_ARCHITECTURE.md`, `04_DATA_MODEL.md`, `05_ANALYTICS_MODEL.md`).

**Если вы считаете, что архитектуру нужно изменить:**
1. НЕ меняйте код
2. Создайте запись в `09_DECISIONS.md` с proposed ADR
3. Обновите `10_KNOWN_ISSUES.md`
4. Оставьте решение следующей LLM или человеку

**Исключение:** Орфографические ошибки и опечатки в документации.

## 4. Обязанности После Завершения Задачи

**После выполнения задачи LLM ОБЯЗАНА:**

### 4.1 Обновить `01_PROJECT_STATUS.md`

```markdown
## Verification Status

| Check | Status | Verified By | Date |
|-------|--------|-------------|------|
| [Ваша задача] выполнена | ✅ Pass | [LLM Name] | 2025-01-XX |
```

### 4.2 Обновить `11_CHANGELOG.md`

Добавить запись в секцию `[Unreleased]`:

```markdown
### Added
- [Что было сделано]

### Changed
- [Что было изменено]

### Fixed
- [Что было исправлено]
```

### 4.3 Написать Отчёт о Работе

Создать файл `reports/PHASE-X.X_REPORT.md` (или обновить существующий):

```markdown
# Отчёт о выполнении PHASE X.X

## Что было сделано

[Подробное описание]

## Какие файлы были созданы/изменены

- `path/to/file1.md` — создание
- `path/to/file2.py` — модификация

## Известные ограничения

[Если есть]

## Рекомендации для следующей LLM

[Если есть]
```

### 4.4 Оставить Репозиторий Готовым к Проверке

**Чеклист перед завершением:**
- [ ] Все файлы закоммичены
- [ ] Нет незакоммиченных изменений
- [ ] Нет временных файлов
- [ ] `.gitignore` соблюдается
- [ ] Документация обновлена
- [ ] Код соответствует стилю (если применимо)
- [ ] Тесты проходят (если применимо)

## 5. Процесс Передачи Следующей LLM

```
┌─────────────────┐     ┌─────────────────┐     ┌─────────────────┐
│   LLM #1        │     │   LLM #2        │     │   LLM #3        │
│   (Phase 0.1)   │────▶│   (Verification)│────▶│   (Phase 0.2)   │
│                 │     │   + Phase 0.2   │     │                 │
└─────────────────┘     └─────────────────┘     └─────────────────┘
       │                       │                       │
       ▼                       ▼                       ▼
  1. Прочитать docs      1. Проверить по        1. Прочитать docs
  2. Выполнить задачу       17_VERIFICATION      2. Выполнить задачу
  3. Обновить статус     2. Записать результат  3. Обновить статус
  4. Написать отчёт         в status/issues      4. Написать отчёт
  5. Оставить готовым    3. Если OK — начать
                            следующую задачу
```

## 6. Нарушение Правил

**Если вы обнаружили нарушение предыдущей LLM:**

1. **НЕ продолжайте разработку**
2. Задокументируйте нарушение в `10_KNOWN_ISSUES.md`
3. Обновите `01_PROJECT_STATUS.md` со статусом "BLOCKED"
4. Оставьте комментарий в PR с указанием нарушения
5. Ждите исправления

**Типы нарушений:**
- 🔴 Critical — платные источники, нарушение архитектуры
- 🟠 High — отсутствие документации, непроходящие тесты
- 🟡 Medium — стилистические проблемы, мелкие недочёты

## 7. Стиль Кода и Документации

### 7.1 Документация

- Пишите на русском языке (кроме технических терминов)
- Используйте Markdown форматирование
- Добавляйте примеры где уместно
- Обновляйте Version History в конце каждого файла

### 7.2 Код (если применимо)

- Следуйте стандартным convention языка
- Добавляйте docstrings/comments
- Пишите тесты для новой функциональности
- Не оставляйте закомментированный код

### 7.3 Коммиты

- Пишите осмысленные сообщения коммитов
- Ссылайтесь на номер фазы/задачи
- Один логический изменение = один коммит (если возможно)

---

## 8. Вопросы и Неопределённости

**Если у вас возник вопрос или неопределённость:**

1. Проверьте документацию ещё раз
2. Если неясно — запишите в `10_KNOWN_ISSUES.md`
3. Если критично — создайте ADR в `09_DECISIONS.md`
4. НЕ принимайте архитектурные решения самостоятельно
