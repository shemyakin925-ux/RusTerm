# Архитектура интерфейса

Нативный десктоп, PySide6, один процесс с ядром (ADR-0004).
Описание экранов и правил, не разметка.

---

## 1. Правила, общие для всех экранов

1. **Интерфейс не считает.** Читает готовую версию снапшота и готовые
   `measure`. Ни одной формулы в слое `app`.
2. **Любое число кликабельно.** Клик открывает панель источника: документ,
   страница или узел, фрагмент текста вокруг числа, дата выгрузки, версия
   парсера, `method_version`. Для производного числа — дерево до первичных
   фактов.
3. **Пробел виден.** Блок в состоянии `missing` или `error` показывается
   с причиной, а не пропадает с экрана. Пустое место читается как «данных
   нет», и это ложь, если данные есть, но не собрались.
4. **`null` — не пустая ячейка,** а прочерк с подсказкой причины
   («знаменатель отрицателен», «менее пяти пиров»).
5. **Неподтверждённый peer set помечен визуально** везде, где показан
   перцентиль или сравнение с отраслью.
6. **Никаких обещаний времени** до того, как оно измерено. Прогресс —
   сделано из общего числа, без прогноза «осталось 4 часа».
7. **Долгие операции не блокируют окно** и допускают отмену. Отмена
   останавливает постановку новых заданий, но не откатывает уже собранное.
8. Все изменения данных проходят через подтверждение и попадают в журнал.

## 2. Экраны

### Список (главный)

Таблица watchlist: инструмент, отрасль, ключевые показатели, покрытие
по блокам, дата последнего обновления, `peer_set_coverage`.

Состояния строки: собран, собирается, устарел, ошибка, частично.
Фильтры по группе, отрасли, состоянию покрытия. Действия: обновить
выбранные, открыть снапшот, экспорт.

При 500 строках таблица работает через модель поверх запроса, без
материализации всех строк в виджете, и без чтения отдельного файла
на каждую бумагу — ради этого `coverage` денормализован.

### Снапшот компании

Блоки README §3.1-3.9 вертикально, с оглавлением сбоку. Каждый блок несёт
свой статус покрытия. Перцентили и бокс-плоты скрыты, если пиров меньше
пяти, — вместо них таблица «бок о бок».

Отдельная вкладка «Что изменилось» с тремя разделами: изменение метрик,
пересостав peer set, появившиеся ревизии. Разделы не смешиваются
(процесс 2, узел 7).

### Отрасль

Peer comparison, агрегаты, цикл, концентрация, лидеры. Открывается кликом
по отрасли из любого места. Показывает состав peer set с версией
и статусом; смена состава — действие с подтверждением, создающее новую
версию.

### Чат

Два режима — по компании и по отрасли, контекст задаётся тем, откуда
открыт. Ответ с числами всегда несёт раздел источников; ответ, не прошедший
проверку цитат, не показывается — вместо него причина. Массовые операции
идут через окно подтверждения со списком (процесс 3).

### Верификация

Очередь: факты `suspect`, документы, не разобранные парсером, помеченные
пользователем числа. По каждому — сырьё рядом со значением, поле для
правильного значения и причины. Правка создаёт факт с `origin=manual`
и предлагает пару в golden-file.

Экран, которого не было в спецификации, и без которого требование 5 свода
невыполнимо.

### Журнал операций

Аудит: что менялось, когда, подтверждено ли, результат. Откат операции
отсюда же. Рядом — метрики провайдеров: success rate, доля отказов
по лимиту, доля `suspect`, лаг данных.

### Настройки

Каталог данных, расписания обновления, пороги свежести, провайдеры
и их лимиты, `raw_retention`, модель и endpoint LLM. Ключ LLM вводится
здесь, хранится в системном хранилище секретов.

## 3. Потоки

| Что | Где выполняется |
|---|---|
| Отрисовка, ввод | поток интерфейса |
| Сбор, парсинг, сборка снапшота, экспорт | пул фоновых потоков |
| Запись в базу | один выделенный поток-писатель |
| Вызовы LLM | фоновый поток, с отменой |

Единственный писатель в базу — следствие ADR-0003 и защита от блокировок
SQLite при параллельном сборе.

---

## 4. Состояния экрана

Каждый экран обязан различать четыре состояния и не показывать их
одинаково: пусто (ничего не собиралось), собирается, собрано частично
с причинами, ошибка сбора. Слияние второго и четвёртого в «крутящийся
индикатор» — самый частый способ спрятать поломку от пользователя.

---

## 5. Тестирование интерфейса

Только smoke: окно открывается, снапшот отрисовывается, экспорт создаёт
файл, чат отдаёт ответ. Логика проверяется в ядре, потому что она вся
в ядре, — это и есть смысл запрета на вычисления в `app`.
