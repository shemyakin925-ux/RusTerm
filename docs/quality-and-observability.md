# Качество и наблюдаемость

Как проверяется, что система считает верно, и как видно, что она сломалась.

---

## 1. Уровни проверок

| Уровень | Что проверяет | Когда гоняется |
|---|---|---|
| Модульные | формулы на синтетических данных, крайние случаи, `null` с причиной | каждое изменение |
| Golden-file на формулы | значения по эталонным эмитентам за 5 лет против выписанных вручную | каждое изменение |
| Golden-file на источники | зафиксированное сырьё → ожидаемые факты, включая локаторы | каждое изменение и по расписанию |
| Тест разрешимости локатора | `resolve(locator)` возвращает то же значение из сырья | каждое изменение |
| Контрактные на провайдера | реализация соблюдает инварианты из `module-contracts.md` | при добавлении провайдера |
| Интеграционные | реальный источник, ограниченный набор | по расписанию, не в каждом прогоне |
| Инвариантные | нет факта без локатора; нет `measure` без lineage; нет перцентиля без версии peer set; `core` не импортирует Qt | каждое изменение |
| Smoke интерфейса | окно, снапшот, экспорт, чат | перед сборкой |

---

## 2. Golden-file: правила

1. Эталон создаётся **до** кода, который его считает. Иначе тест проверяет
   код против самого себя.
2. Эталон меняется только вместе с `method_version`. Правка ожидаемого
   значения без новой версии формулы — запрещённая операция, и это
   проверяется отдельно.
3. Каждая правка из процесса верификации предлагается кандидатом
   в golden-file: ручной труд превращается в постоянную защиту.
4. Набор: 5 эмитентов на рынок, разные отрасли, обязательно один
   с отрицательной прибылью, один со сменой финансового года, один
   с ревизией прошлых периодов. Крайние случаи в эталоне важнее объёма.

## 3. Системные метрики

Из требования 4 свода. Хранятся в `metric_sample`, показываются в журнале
операций — не только в логах, иначе их никто не увидит.

| Метрика | Смысл | Тревожно, когда |
|---|---|---|
| `provider_success_rate` | доля успешных запросов | резкое падение — источник закрылся или заблокировал |
| `provider_rate_limited` | доля отказов по лимиту | рост — темп запросов надо снижать |
| `data_lag` | возраст самых свежих данных по блоку | превышает порог свежести кратно |
| `suspect_share` | доля фактов, не прошедших валидацию | рост — сменился формат источника |
| `unparsed_share` | доля неразобранного в документах | рост — то же |
| `verification_queue` | размер очереди ручной верификации | растёт монотонно — автоматика не справляется |
| `peer_set_coverage` | доля бумаг с подтверждённым набором | низкая — перцентили в основном неподтверждённые |
| `peer_set_churn` | дрейф состава за проход | выше 20% — блокирует diff по перцентилям |
| `locator_resolve_failures` | локаторы, не разрешающиеся в сырьё | любое ненулевое значение — сигнал |

Последняя — самая ранняя из всех: она ловит смену формата источника
раньше, чем неверное число дойдёт до экрана.

## 4. Логи

Три назначения, не смешиваются:

- `logs/app.log` — работа приложения, ротация по размеру.
- `logs/audit.jsonl` — операции пользователя, только добавление, должен
  пережить потерю базы.
- `raw/manifests/*.jsonl` — журнал загрузок, ведущий по отношению
  к таблице `raw_object`.

## 5. Критерии готовности фаз

Фаза считается закрытой по факту прогона, не по ощущению. «Готово
к использованию» без прогона — недопустимая формулировка.

| Фаза | Критерий |
|---|---|
| M1 Скелет | повторный сбор одного эмитента не создаёт дублей ни в store, ни в фактах — доказано тестом идемпотентности |
| M2 Факты US | по 5 эмитентам ключевые показатели за 5 лет совпадают с golden-file; каждое число разрешается до XBRL-факта |
| M3 Снапшот | снапшот по 20 эмитентам собирается одним проходом; недостающие блоки показаны с причиной |
| M4 Watchlist | 500 бумаг обновляются инкрементально по расписанию; откат списка на дату восстанавливает состав |
| M5 LLM | тест подтверждает: каждое числовое утверждение несёт ссылку; ни одна массовая операция не исполняется без подтверждения |
| M6 UK и CA | те же golden-file проходят на 3 эмитентах каждого рынка **без правок в `core`** |
| M7 Industry View | агрегаты по сектору воспроизводятся на исторической дате с тем же составом peer set |
