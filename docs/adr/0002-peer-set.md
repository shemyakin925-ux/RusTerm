# ADR-0002. Peer set — версионируемая сущность

**Статус:** принято (06.09.2026)

## Контекст

На наборе пиров держится половина продукта: peer comparison (§3.7), перцентили
и бокс-плоты, отраслевые агрегаты, цикл индустрии, концентрация (§4), а также
часть governance-оценок, которые осмысленны только относительно сектора.

Бесплатной отраслевой классификации приемлемого качества не существует.
SIC у SEC грубый и устаревший, GICS платный, у провайдеров цен классификация
своя и меняется без предупреждения.

Опасность не в том, что peer set неточен — с этим можно жить. Опасность в том,
что он **молча меняется между проходами**. Тогда перцентиль компании
изменится не потому, что изменилась компания, и блок «что изменилось» (§3.8)
покажет пользователю ложное изменение, которому он поверит. Это хуже, чем
отсутствие метрики.

## Решение

**Peer set — не свойство, вычисляемое на лету, а именованная версионируемая
сущность с зафиксированным составом на дату и обязательным происхождением.**

### Схема

```
PeerSet{
  peer_set_id,
  scope: {kind: "company" | "industry", ref: instrument_id | industry_id},
  version, valid_from, valid_to,
  origin: manual | catalog | classifier | llm_suggested,
  method_version,
  approved_by_user: bool, approved_at,
  criteria: {…},          # для динамических наборов: сектор, капитализация, биржа
  members: [ {instrument_id, included_from, excluded_from, reason} ]
}
```

### Приоритет источников

| Origin | Приоритет | Применяется автоматически |
|---|---|---|
| `manual` — список пользователя | 1, побеждает всегда | да |
| `catalog` — из `docs/industry-metrics/<industry>.md` | 2 | да |
| `classifier` — классификация провайдера | 3 | да |
| `llm_suggested` — предложение LLM | 4 | **нет, только в очередь на подтверждение** |

Каталог отраслевых метрик уже содержит раздел «Peer set по умолчанию» —
он становится основным рабочим источником. Для 30-150 бумаг составить
эти списки руками реалистично, и это честнее любой автоклассификации.

### Правила

1. **Заморозка на проход.** Каждый снапшот записывает `peer_set_version`,
   с которой считались перцентили. Перцентиль без версии peer set —
   невалидное число, как факт без локатора (ADR-0001).
2. **Diff считается дважды.** «Что изменилось» показывает раздельно:
   изменение метрик при **старом** составе (чистое изменение компании)
   и эффект пересостава (`в peer set добавлены X, Y; исключён Z`).
   Смешивать эти две величины в одном числе запрещено.
3. **Порог дрейфа.** `peer_set_churn` за проход больше 20% состава →
   снапшот помечается `suspect`, перцентили показываются, но блок
   «что изменилось» по ним не строится, пока пользователь не подтвердит
   новый состав.
4. **Минимальный размер.** Меньше 5 членов — перцентили, бокс-плоты
   и радар не рисуются вообще, показывается таблица «бок о бок».
   «Компания в 90-м перцентиле из трёх» не выводится ни при каких условиях.
5. **Override дёшев и обязателен по причине.** Действие «исключить X
   из пиров» создаёт новую версию с `origin=manual`, поле `reason`
   обязательно к заполнению.
6. **Воспроизводимость.** Запрос снапшота на историческую дату обязан
   вернуть тот состав peer set, который действовал тогда. Проверяется
   golden-file тестом Фазы 4.

### Роль LLM

LLM участвует ровно в одном месте: предлагает кандидатов в пиры по описанию
деятельности (§6.4). Предложение попадает в очередь с обоснованием по каждому
кандидату и не применяется, пока пользователь не подтвердит. LLM не меняет
состав действующего peer set и не влияет на расчёт перцентилей.

## Следствия

1. `core/peers/` — отдельный модуль с собственным хранилищем версий,
   а не поле в таблице компаний.
2. Каталог `docs/industry-metrics/` из справочника превращается в
   эксплуатируемые данные: каждая отрасль, которую пользователь реально
   смотрит, требует поддерживаемого списка пиров.
3. В UI у каждого перцентиля появляется подпись с версией и размером peer set.
   Это дополнительная работа по интерфейсу, но без неё правило 1 бессмысленно.
4. Industry View (Фаза 8) строится поверх этого модуля и не заводит
   собственную классификацию.

## Отвергнутые варианты

- **Автоклассификация по SIC/GICS без версионирования.** Даёт молчаливый
  дрейф — ровно тот риск, ради которого написан этот ADR.
- **Peer set как ручной список без модели версий.** Не позволяет
  воспроизвести исторический снапшот и ломает diff.
- **Кластеризация по финансовым признакам.** Состав меняется от прогона
  к прогону сильнее, чем классификация; для персонального инструмента
  на 150 бумагах выигрыш не окупает непредсказуемости.
