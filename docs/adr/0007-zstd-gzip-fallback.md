# ADR-0007. Фолбэк сжатия: zstd → gzip

**Статус:** принято агентом, требует подтверждения (07.09.2026)

## Контекст

Хранилище сырых объектов (`rusterm/store/raw_store.py`) сжимает всё, что
не меньше 64 КБ. Основной алгоритм — `zstandard`, но пакет разрешён, а не
гарантирован: машина пользователя может быть без него. Выкидывать сжатие
нельзя (объёмы сырых ответов API большие), падать при отсутствии пакета
тоже нельзя. Поэтому `raw_store.py` фолбэчит на `gzip` из стандартной
библиотеки, а конкретный алгоритм записывается в поле `compression`
метаданных (`zstd` | `gzip` | `none`).

Схема базы этому противоречила: `CHECK (compression IN ('none','zstd'))`
в таблице `raw_object` отвергал gzip-объекты с `IntegrityError`. Править
существующую миграцию нельзя (I11: база с данными обязана пережить
миграцию; переписанная задним числом миграция — ровно то, что I11
запрещает).

## Решение

1. **Миграция 33** (новая, поверх неприкосновенных миграций 1–32):
   `schema_version` поднят до 33, таблица `raw_object` перестроена штатным
   для SQLite путём — `PRAGMA foreign_keys=OFF`, создание `raw_object_new`
   с `CHECK (compression IN ('none','zstd','gzip'))`, перелив всех строк,
   удаление старой таблицы, переименование, возврат `PRAGMA`, всё в одной
   транзакции.
2. **Выбор алгоритма при записи:** `zstandard` доступен — пишем zstd;
   недоступен — gzip (уровень 6); меньше порога — без сжатия. Алгоритм
   фиксируется в метаданных и в расширении файла (`.zst` / `.gz`).
3. **Чтение объектов обоих видов:** метка `compression` выбирает
   декомпрессор; при утере метки — определение по magic-байтам
   (`28 B5 2F FD` — zstd, `1F 8B` — gzip). Читается любой из видов
   независимо от того, какой алгоритм доступен сейчас: для чтения gzip
   достаточно стандартной библиотеки.
4. **Появление `zstandard` на машине, где уже лежат gzip-объекты:**
   новые объекты начнут писаться как zstd, существующие gzip-объекты
   продолжают читаться (через метку и magic-байты), миграции и перезапись
   не требуют. Обратный переход (удаление `zstandard`) симметричен.

## Отвергнутые варианты

- **Правка CHECK в существующей миграции 9** — нарушает I11: у
  пользователя уже может лежать база; ALTER ограничение в SQLite не
  умеет, а пересоздание таблицы задним числом ломает применённые базы.
- **Требовать `zstandard` обязательно** — пакет не входит в разрешённый
  список и может отсутствовать; падение хранилища на пакете недопустимо.
- **Хранить алгоритм только в расширении файла, без метки в БД** — метка
  в `raw_object.compression` нужна сверке и инспекции без файловой
  системы.

## Следствия

- Тесты сжатия проверяют существо (объект сжат, читается обратно тем же
  алгоритмом), а не конкретную метку; метка `zstd` фиксируется отдельным
  тестом с пропуском при отсутствии пакета.
- Проверка 11 приёмки (прогон с заблокированным `zstandard`) — рабочая
  регрессионная защита фолбэка.
