# ADR-0007. Zstd/Gzip compression fallback

**Статус:** принято агентом, требует подтверждения (07.09.2026)

## Контекст

`raw_store.py` использует `zstandard` как основной алгоритм сжатия при его доступности, иначе падает back на `gzip` из стандартной библиотеки. База данных имеет CHECK-constraint на таблице `raw_object`, ограничивающую допустимые значения `compression` до `('none', 'zstd')`. Однако `raw_store.py` уже умеет писать `compression="gzip"` как fallback, и этот фолбэк необходим для работы без установленного `zstandard` пакета.

Согласно `TASK-3.md` §3: «Запрещены: любой ORM, alembic, pandas, numpy, асинхронные фреймворки, всё, чего нет в таблице... Никаких `from typing import list` и подобного: `list`, `dict`, `tuple`, `set` — встроенные типы, в `typing` их нет и не было.»

## Решение

1. **CHECK-constraint в БД** обновлен: `compression IN ('none', 'zstd', 'gzip')` — теперь допускаются три значения.

2. **Логика выбора алгоритма в `raw_store.py`**:
   - Если установлен пакет `zstandard` — используем `zstd` (выше compression ratio, быстрее при больших объёмах)
   - Если `zstandard` недоступен — используем `gzip` из stdlib
   - Метка `compression` записывается в метаданные объекта, чтобы последующее чтение знало, какой алгоритм применить
   - При чтении: если на meta записан `gzip`, читаем через `gzip.decompress`, если `zstd` — через `ZstdDecompressor`, если `none` — возврат без декомпрессии
   - Magic-number detection (`_is_zstd_magic`, `_is_gzip_magic`) как fallback при отсутствии метки

3. **Обратная совместимость**:
   - Already-stored объекты с `compression='none'` читаются как есть
   - Already-stored объекты с `compression='zstd'` читаются через zstd path
   - Новые объекты могут иметь `compression='gzip'` при отсутствии zstandard

4. **ADR о forced replacement** — решение переживёт ночь, так как:
   - Пользователь может поднять систему и на машине без `zstandard`
   - База данных с `gzip`-объектами будет читаться корректно
   - При появлении `zstandard` на существующей базе `gzip`-объекты продолжат читаться

## Следствия

1. Всем модулям store разрешено писать `compression='gzip'` — CHECK-constraint это теперь разрешает.
2. Тесты, проверяющие `compression == "zstd"` жестко, должны быть обновлены: алгоритм зависит от наличия пакета, а конкретная метка (`zstd` или `gzip`) фиксируется в метаданных.
3. Добавлен новый ADR (0007) с объяснением выбора алгоритма и стратегии миграции.
4. `schema_version` миграция добавлена с обновлением CHECK-constraint (см. fix A1 выше).

## Отменённые варианты

- Не изменять CHECK-constraint — это приведёт к `IntegrityError` при попытке записать `gzip`-объект в существующую базу.
- Слаботеть тест на конкретную метку `zstd` — тест должен проверять round-trip сжатия, а не хардкод имя алгоритма.
