# ADR-0009. Терминальный интерфейс раньше десктопного

**Статус:** принято (решение ТЗ-8, U11), требует подтверждения пользователя.

## Контекст

ADR-0004 выбрал PySide6 для десктопного приложения, но проверка 6
приёмки запрещает Qt в дереве целиком — и эта проверка не обсуждается:
интерфейсная зависимость в ядре тащит за собой сборку, лицензию и
поверхность атаки ради «кнопок», которых в ядре ещё нет. При этом
программа уже работает (`TASK-8` U3): у пользователя есть инструменты,
снапшоты, покрытие и governance — а смотреть на них можно только через
`export`.

## Решение

**Интерфейс сейчас — терминальный (`rusterm tui`, stdlib `curses`),
десктоп остаётся целью (ADR-0004 не отменяется).**

- Два экрана из `docs/ui-architecture.md` §2: «Список» (watchlist с
  восемью ячейками покрытия на строку) и «Карточка» (меры, покрытие с
  причинами, governance пятью цветами, панель источника).
- Разделение слоёв: содержимое экранов собирают чистые функции
  `rusterm/tui/model.py` над репозиториями; `curses` только красит.
  Отсюда тестируемость без терминала (`tests/test_tui_model.py`).
- Жёсткие правила: TUI ничего не считает (нет формул), не пишет в базу,
  не ходит в сеть; SQL вне `rusterm/store/` по-прежнему запрещён.
  Длинные операции из TUI не запускаются.

## Что TUI не делает

Не изменяет состояние, не выполняет массовые операции, не показывает
запросы подтверждения (для этого есть CLI и будущий десктоп), не
рисует графики.

## Следствия

- ADR-0004 остаётся целью для десктопной сборки; PySide6 появится
  только как зависимость интерфейсного слоя, когда ядро и данные
  перестанут меняться каждую ночь.
- Новые экранные возможности сначала попадают в `model.py` (и в
  headless-тесты), потом в отрисовку.
