# ADR-0030. Операционная прибыль без своей строки (вывод из pretax и процентов)

**Статус:** принято (22.10.2026, ТЗ-143 F1)

## Контекст

PFE и XOM не подают тег `OperatingIncomeLoss` вовсе: вся цепочка мер
(ebitda, операционная маржа, roic, nopat, ev_ebitda, net_debt_ebitda,
interest_coverage) честно отказывала, карточки обеих компаний стояли на
70 % (REPORT-141). Словарь данных (docs/data-dictionary.md §2,
«operating_income = operating income») предполагает строку; файл
заморожен (пункт 10 приёмки: docs/ меняется только новыми ADR), поэтому
расширение словаря живёт здесь и именует себя в тесте-страже
(tests/test_concept_map.py принимает имя концепта в словаре ИЛИ в ADR).

## Решение

1. **Карта концептов** (us-gaap.v9): `interest_income` <-
   `InvestmentIncomeInterest` — процентные доходы, третье слагаемое
   вывода.
2. **Правило одной функцией** (`rusterm/core/operating.py`):
   `operating_income = pretax_income + interest_expense −
   interest_income`; процентные доходы не поданы — ноль; нет прибыли до
   налогов или процентных расходов — вывода нет. Одно правило для
   снапшота и карточки.
3. **Приоритет своего тега**: на период (unit, start, end), где тег
   операционной прибыли подан, вывод не применяется (ранг выведенной
   строки — дно).
4. **Именование в родословной**: роль входа, собранного из выведенной
   строки, называет правило («выведено: pretax_income +
   interest_expense − interest_income»).
5. **IFRS не тронут**: там своя строка операционной прибыли в карте
   (`ProfitLossFromOperatingActivities`).

## Следствия

- Карточки PFE и XOM: 70 % → 94 %/92 % (замер на копии базы, ТЗ-143).
- Сверка с Yahoo: контрольная десятка не изменилась (99 %); расхождения
  operating_income у PFE/XOM — методика Yahoo (разовые статьи), названы
  в REPORT-143.
- Долг XOM (парный тег с финансовым лизингом) — отдельное решение,
  ТЗ-143 F2 (REPORT-143).
