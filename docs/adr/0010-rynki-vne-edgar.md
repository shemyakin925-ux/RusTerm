# ADR-0010. Рынки вне EDGAR: провайдер на рынок и уровень доступности

**Статус:** принято (решение пользователя, дополнение от 10.09.2026).
Отменяет правило «один источник — SEC EDGAR» (ТЗ-18 §1.12 N1).

## Контекст

До сих пор источник был один: SEC EDGAR. Рынки US, CA и OTC работают
через `companyfacts` и файлы тикеров SEC — реестр рынков
(`rusterm/markets.py`) уже существует, но все три строки указывают на
одного провайдера `edgar`.

Пользователь расширил область: нужны **Корея, Бразилия, Австралия** и
углубление **US-OTC**. Великобритания снята с повестки полностью.
Канада остаётся: она построена, зелена и несёт словарь `ifrs-full`,
на котором стоят все три новых рынка.

Живая проверка каналов выполнена и записана в `agent/REPORT-MARKETS.md`
(замеры от 09–10.09.2026, не предположения):

| Рынок | Канал | Замер | Что это значит |
|---|---|---|---|
| KR | Open DART (FSS), официальный API | `engopendart.fss.or.kr/engapi/list.json` → 200 JSON, просит ключ | бесплатный ключ по регистрации, английские отчёты, выгрузка XBRL, бот-стены нет |
| BR | CVM open data, `dados.cvm.gov.br` | `dfp_cia_aberta_2024.zip` HEAD → 200, 13 396 366 байт | регулятор раздаёт CSV/ZIP без ключа; публичного API нет до 2026–2028 |
| AU | ASX + `asx.api.markitdigital.com` | `/asx-research/1.0/companies/CBA/announcements` → 200 JSON | открытые эндпойнты без авторизации; официальный маршрут — платный ASX DataAPI |
| US-OTC | OTC Markets Group | `otcapi/company/{SYM}/financial-report` → 200 JSON с браузерными заголовками; `/content` закрыт | индекс и метаданные раскрытий бесплатны; байты документов — нет |

Три из четырёх каналов различаются по природе: официальный API с ключом
(KR), пакетная выгрузка файлов (BR), недокументированные открытые
эндпойнты биржи (AU). Один провайдер их не покроет.

## Решение

**Каждый рынок обслуживает свой провайдер, и рынок объявляет уровень
доступности данных.**

### 1. Провайдер на рынок

`rusterm/markets.py` уже несёт поле `provider`. Новые строки реестра
указывают на своих: `KR -> dart`, `BR -> cvm`, `AU -> asx`,
`OTC -> otcmarkets` (при этом OTC-эмитенты, отчитывающиеся в SEC,
по-прежнему идут через `edgar` — см. §3).

Провайдер живёт в `rusterm/providers/<имя>.py`, реализует тот же
`DisclosuresProvider`, регистрируется в `_NETWORK_PROVIDERS` и **не может
быть выдан без `RequestGate`** — правило ТЗ-8 U5 не ослабляется ни для
одного нового источника.

### 2. Уровень доступности — поле реестра, а не знание в голове

`Market` получает поле `access: str` из трёх значений:

- `auto` — эмитенты рынка скачиваются программой целиком и без участия
  человека (US, CA, KR, BR);
- `partial` — часть эмитентов скачивается, часть нет; программа обязана
  различать их **до** создания эмитента (AU, OTC);
- `manual` — автоматической загрузки нет вовсе; единственный путь —
  ручной импорт документов (ADR-0011). Строк с этим значением сейчас
  нет; поле существует, чтобы следующий рынок стоил одну строку.

### 3. Правило пользователя: только то, что качается само

Пользователь сформулировал прямо: **добавляются только те компании,
которые можно скачать автоматически; в остальных случаях программа
предлагает добавить файлы отчётов вручную.**

Отсюда обязанность команды `add`: перед созданием эмитента провайдер
рынка отвечает на вопрос «этот эмитент забирается автоматически?».
Три исхода, все — значения, не исключения:

| Исход | Что делает программа |
|---|---|
| эмитент забирается | обычный путь сбора |
| эмитент известен, но раскрытия недоступны машинно | эмитент **не создаётся молча**: `manual_import_required` с именем команды ручного импорта в тексте |
| эмитент неизвестен рынку | `unknown_issuer`, exit 1 |

`manual_import_required` — причина покрытия наравне с
`no_sec_filings` (ТЗ-18 G5): честный ответ, а не падение и не тишина.
Предложение ручного импорта — единственное место, где программа
советует пользователю действие.

### 4. Границы, которые не двигаются

- HTTP по-прежнему только в `rusterm/providers/` (проверка 8 приёмки).
- Провайдер не знает о хранилище (I10, проверка 9).
- Каждый новый источник несёт **свой лимит запросов и своё имя в
  `RequestGate`**: лимит SEC (5 запросов/с) не наследуется чужим хостом
  и не применяется к нему.
- Ключи источников — только через переменные окружения
  (`RUSTERM_DART_KEY` и подобные), никогда в git. Ключ не задан —
  `ConfigError` значением и офлайн-путь, как `RUSTERM_SEC_UA`.
- Тесты не ходят в сеть: у каждого рынка **записанный обрезанный
  payload** под `tests/data/<провайдер>/`, и golden-тест разрешает
  каждое значение обратно в payload по указателю.

### 5. Правовая осторожность

`asx.api.markitdigital.com` и `otcapi` — открытые, но не заявленные как
публичные API. Провайдеры для них помечаются в коде и в README как
**канал без договора**: вежливый темп, браузерных заголовков ровно
столько, сколько нужно для ответа, никакой массовой выкачки, отказ от
обхода блокировок. 403 и 429 — остановка, а не задача (N4 остаётся).

## Следствия

- `README.md` §15: веха «M6. UK и CA» больше не соответствует
  действительности — UK снят, CA закрыт. Требуется отдельная веха
  **M8 «Рынки KR, BR, AU и углубление OTC»**; правка README — пункт ТЗ,
  а не самодеятельность исполнителя.
- Правило N1 «единственный источник — EDGAR» в новых ТЗ заменяется на
  «источник задаётся строкой реестра рынка».
- Стоимость следующего рынка после этого ADR: строка в `MARKETS`,
  файл провайдера, записанный payload. Логика сбора не правится —
  ради этого реестр и заводился (ТЗ-18 G1).
