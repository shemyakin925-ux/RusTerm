# ADR-0004. Нативный десктоп на PySide6 (Qt)

**Статус:** принято (06.09.2026)

## Контекст

Оболочка UI была открытым вопросом с двумя кандидатами: веб-морда локально
и нативный десктоп. Решение пользователя — **нативный десктоп**.

Ограничения, в которых выбирается фреймворк:

- Ядро — Python: XBRL, парсинг отчётности, расчёты, pandas (README §11.2).
- Разработчик один. Каждая дополнительная граница между языками и процессами —
  постоянный налог, а не разовая стоимость.
- Данные локальные, сервера нет (ADR-0003). Сетевого слоя между UI и ядром
  быть не должно вовсе.
- Основная нагрузка на UI — таблицы до 500 строк, временные ряды на 2 500
  точек с оверлеями, бокс-плоты и радары по peer set.

## Рассмотренные варианты

| Вариант | Плюсы | Минусы | Итог |
|---|---|---|---|
| **PySide6 (Qt)** | тот же язык, что ядро; один процесс, без IPC; нативные виджеты и таблицы; LGPL | визуально «системный», а не веб-модный; кривая обучения Qt-моделей | **выбран** |
| Tauri + web-фронт | лучший внешний вид, знакомый стек вёрстки | Rust-оболочка + Python-сайдкар + IPC = три технологии и постоянная граница | отклонён |
| Electron + Python-сайдкар | зрелая экосистема | 150+ МБ на пустом месте, два процесса, тот же IPC | отклонён |
| Flutter | один UI на все платформы | Dart — третий язык, обязательный мост к Python, выигрыш «одна кодовая база» бессмыслен при одной целевой платформе | отклонён |

## Решение

1. **PySide6** — официальные Qt-биндинги под LGPL. Не PyQt6: тот под GPL,
   и при любой мысли о раздаче приложения лицензия становится проблемой.
2. **Один процесс.** UI вызывает `core` напрямую как библиотеку. Никакого
   REST, никакого локального сервера, никакой сериализации между слоями.
3. **Длинные операции — в `QThreadPool`**, не в UI-потоке. Сбор снапшота
   по watchlist на 500 бумаг идёт фоново, с прогрессом и возможностью отмены.
   Обращение к БД — из одного выделенного потока-писателя (ADR-0003).
4. **Таблицы — `QAbstractTableModel`** поверх результата запроса, без
   материализации всех строк в виджете. При 500 бумагах это не критично,
   но задаёт правильную границу сразу.
5. **Графики — `pyqtgraph`** для временных рядов и интерактива (цена,
   drawdown, TCE по классам судов), **QtCharts** для простой столбчатой
   и box-plot графики. Matplotlib — только для экспорта картинок в отчёты.
6. **Сборка — PyInstaller** в `.app` под macOS. Подпись и нотаризация нужны
   только при раздаче третьим лицам; в текущем режиме личного использования
   не требуются.

## Следствия

1. Слой `app/` зависит от `core/`, обратной зависимости нет. `core` не
   импортирует Qt ни в одном месте — иначе ядро нельзя будет прогнать
   в тестах и в CLI.
2. CLI-режим сохраняется как первоклассный: `ingest`, `snapshot`, `export`
   работают без UI. Это то, на чём строятся golden-file тесты Фаз 1-2,
   и это же страховка, если Qt окажется тупиком.
3. Тестируется ядро, а не виджеты. UI-тесты — только smoke: окно
   открывается, снапшот рисуется, экспорт создаёт файл.
4. Кроссплатформенность бесплатна с точки зрения кода, но не с точки
   зрения проверки: заявляется только macOS, пока не проверено на другой ОС.

## Риск

**Qt-модели — не то, что знает большинство и что хорошо подсказывают
языковые модели.** Ошибки в `QAbstractTableModel` и сигналах между потоками
дают редкие плавающие падения, которые дороги в отладке. Снижается правилом 1:
вся логика в `core` и покрыта тестами, в `app/` остаётся только отображение.
