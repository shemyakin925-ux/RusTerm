# ADR-0021. TTM не строится из XBRL эмитента без квартального факта четвёртого квартала: годовое приближение видно в lineage

**Статус:** принят (исполнитель, 15.09.2026, по вердикту координатора
ТЗ-32, пункт 4: «approved as annual, not TTM»).

## Контекст

Словарь задаёт `ev_ebitda = ev / ebitda_ttm` и `roic = nopat /
invested_capital` — знаменатели именованы как TTM. Замер ТЗ-31 на
живых данных Apple показал, что TTM из XBRL companyfacts построить
нельзя честно ни одним способом:

- квартальный факт за фискальный Q4 (июль–сентябрь) эмитент НЕ
  подаёт: годовой 10-K содержит 12-месячный период, а не 3-месячный
  четвёртый квартал;
- алгебра «год + YTD − YTD прошлого года» падает: для TTM на
  2026-06-27 нужен 9-месячный факт прошлого года
  (2024-09-29 → 2025-06-28), которого в fact-наборе нет;
- сумма «последних четырёх кварталов» падает по той же причине
  (Q4 отсутствует).

Подмена одной TTM-величины другой (дивиденды выплаченные вместо
начисленных, денежный поток вместо прибыли) — выдумка, а не расчёт.

## Решение

1. **Знаменатели ev_ebitda и roic считаются по последнему общему
   ГОДОВОМУ периоду (350–380 дней) входных фактов** — честный
   12-месячный эквивалент TTM, periods которого видны в строках
   мер и lineage. Нет годового общего периода — `missing_data`, не
   подмена.
2. **База периода перестаёт быть невидимой (ТЗ-32 D6):** миграция 43
   добавляет `period_basis (ttm | annual)` в обе таблицы lineage.
   Годовое приближение помечает свои строки `annual`; TTM-окно
   `dps_ttm` по корпоративным действиям — `ttm`; NULL — прямой
   однопериодный вход.
3. **Последствия:** пользователь видит в lineage, что числитель и
   знаменатель считены на разных основах периодов; снапшот Apple
   показывает ev_ebitda = 33.9 при годовой ebitda FY2025 —
   обычный trailing-мультипликатор, а не четвертной, умноженный на
   четыре.
