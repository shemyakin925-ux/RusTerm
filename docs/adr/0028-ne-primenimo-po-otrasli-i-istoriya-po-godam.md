# ADR-0028. «Не применимо» по отрасли и история мер по финансовым годам

**Статус:** принят (ТЗ-107, 01.10.2026, по скриншоту пользователя от
30.09.2026). Не меняет существующих документов.

## Контекст

На базе пользователя у банка (BAC) таблица показывала только «сейчас» и
2026, график — одну точку на оси с дробными датами, а EBITDA, EV и FCF —
«нет данных». Причины: снапшоты строились только на дату запуска; ось
pyqtgraph подписывала узкий диапазон дробями; меры, которые для банка не
определены, выглядели как пробел в данных.

## Решение

1. **История по годам.** `rusterm history --instrument X | --all` строит по
   снапшоту на конец каждого финансового года (до 10 лет) из уже лежащих
   фактов, без сети. Дата сборки — конец года, дверь `as_of` не пускает
   более поздние периоды. Уже построенный год не строится заново; после
   новых лет последним пересобирается текущий снапшот, чтобы «сейчас»
   осталось текущим.
2. **График по целым годам.** Деления оси — ровно годы ряда.
3. **«Не применимо».** Для отрасли `banks` меры `ebitda`, `ev`,
   `ev_ebitda`, `fcf`, `fcf_yield`, `gross_profit`, `gross_margin`,
   `net_debt`, `net_debt_ebitda`, `interest_coverage`, `capex`,
   `capex_to_revenue`, `roic`, `invested_capital` без числа получают
   причину `not_applicable: banks`, окно пишет «не применимо к банкам».
   Если число всё же посчитано, оно не скрывается.
4. **Сырьё.** Сжатый ответ (`<sha>.gz`, `<sha>.zst`) — это сохранённое
   сырьё; панель источника находит его и не пишет «сырья нет».
