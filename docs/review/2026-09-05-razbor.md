# Разбор рецензии minimax (05.09.2026)

Рецензент видел только README и не знал результатов замеров. Часть замечаний
поэтому бьёт мимо, часть — точно в цель. Ниже сортировка.

## Принять

1. **Cut-line MVP.** Главное замечание и справедливое: фазы 0-6 — это roadmap
   продукта, а не ТЗ на первый релиз. Нужна одна фраза, что входит в MVP,
   и явное «всё остальное — потом».
2. **Data lineage на каждое число, а не только на governance-балл.** Источник,
   URL, дата выгрузки, версия парсера, ссылка на raw. README требует
   прослеживаемость для governance; распространить на все показатели.
3. **Версионировать все формулы, не только веса governance.** TR, ROIC,
   перцентили. Иначе через год свои же цифры не воспроизвести.
4. **Observability ingestion.** Success rate, лаг, доля suspect, доля событий,
   ушедших на ручную верификацию. Смыкается с canary-проверкой полноты.
5. **Процедура исправления ошибок извлечения и хранилище ground truth.**
   Роль верификатора в README не описана вовсе — рецензент нащупал то же место.
6. **Экспорт в CSV/Excel.** Дёшево, а для работы с 30-150 бумагами обязательно.
7. **UX-сценарии вместо «лучшего снапшота».** Продукт описан набором таблиц,
   а не задачами пользователя.
8. **Threat model источников.** Что делаем, если ISS закроет бесплатный доступ
   или сменит формат. Ни одного fallback в ТЗ нет.

## Отклонить или смягчить

1. **«Реестр обещаний ретроспективно невозможен, только форвард».** Слишком
   пессимистично. Годовые отчёты за 5-10 лет доступны на порталах раскрытия
   и содержат дивполитику, гайденс и стратегические цели — это восстановимо
   для 10-20 эмитентов ручной работой. Невосстановимы именно презентации
   и версии IR-страниц, то есть «тихие отмены». Разделять эти два случая.
2. **«CAPTCHA и антибот на e-disclosure».** Не подтверждено замером: капчи нет,
   есть отсечение по географии. Реальная проблема другая и уже решается VPN.
3. **«Corporate actions неразрешимы».** Преувеличение. ISS отдаёт часть событий
   машинно; ручной остаётся верификация по 20-30 бумагам, а не по всем.
4. **«Governance — отдельный коммерческий проект, встраивать = провал обоих».**
   Это уже не оценка ТЗ, а совет закрыть проект. Governance — единственное,
   что отличает терминал от бесплатных скринеров; выбросив его, получим
   ещё один smart-lab.
5. **Оценка «8-15 человеко-лет».** Направление верное, число взято с потолка.

## Требует решения пользователя

- **Flutter в MVP или web-UI.** Рецензент предлагает web + PWA и отложить
  Flutter. Совпадает с открытым вопросом ADR-0002 по desktop-оболочке.
- **Объём MVP:** 15-20 бумаг без governance и факторов — или governance
  с первого дня на 10 эмитентах, как настаивает исходное ТЗ (§8, фаза 4
  раньше факторов).

## Юридическое замечание, которого не было ни у кого

Риск иска о защите деловой репутации со стороны мажоритария на governance-скор.
В текущем режиме (личное использование, приложение никому не раздаётся) риск
близок к нулю, но при публичной раздаче становится реальным и требует
проработки до, а не после. Дописать в §11 README.
