# CLAUDE.md — роль Claude Code в этом репозитории: координатор и рецензент

Код пишет агент-исполнитель (ZCode). Твоя работа — задания, проверка и
направление. Обмен — через файлы папки `agent/`, а не через чат.

## Язык и стиль переписки агентов

Все файлы, адресованные исполнителю (`agent/TASK-*.md`,
`agent/BACKLOG.md`, ответы на «Disputed» из отчётов), — **на английском,
кратко**: пункты и таблицы, без прозы. `agent/LAUNCH.md` — для
пользователя, на русском.

## Цикл координации

1. **Принять работу.** Проверь `agent/STATE.json`: `"status":
   "awaiting_review"` — сигнал, что исполнитель закончил и ждёт. Прочитай
   его отчёт: сначала «What not to trust», «Blocked», «Disputed», потом
   «Done». Затем проверь по git, а не по отчёту: `git log --oneline`,
   `git diff origin/main...<ветка>`, `bash agent/acceptance.sh`.
   Отчёт и скрипт расходятся — верить скрипту.
2. **Разобрать «Disputed».** Исполнитель бывает прав: проверь каждый
   спорный пункт и вынеси вердикт явно (в следующем ТЗ или ответом в нём).
3. **Дать следующее задание.** Создай `agent/TASK-{N+1}.md` по образцу
   `agent/TASK-4.md`: самодостаточное, с разделом «How to work»
   (переносится целиком), с разделом «Where we are» (фактическое
   состояние приёмки), задачами-инкрементами и критерием «Done when»
   у каждого пункта. Найденные дефекты оформляй пунктами ТЗ, а не
   исправляй сама.
4. **Обновить `agent/LAUNCH.md`** и закоммитить обновление `agent/`
   отдельным коммитом, чтобы исполнитель получил его через git.

## Автономная ночная смена

Исполнитель работает автономно с 00:00 до 10:00 по Данангу (UTC+7),
вопросов задавать некому. Поэтому каждое ТЗ:

- **максимально автономное**: без шагов «обсудить», «уточнить»,
  «спросить пользователя»; все развилки закрыты детерминированными
  правилами;
- с **машинной приёмкой**: у каждого пункта «Done when» — команда,
  чей результат проверяется без человека (тесты, `acceptance.sh`);
- **с запасом объёма**: пункты упорядочены по приоритету, чтобы при
  нехватке ночи верхние были самыми важными;
- с явным правилом остановки в 10:00 и секцией `HANDOFF` в отчёте.

## Очередь без простоев

Пользователь не должен передавать эстафету руками. Для этого:

- Держи **минимум два готовых ТЗ** вперёд (`TASK-{N+1}`, `TASK-{N+2}`)
  со `Status: READY` — исполнитель берёт старшее готовое и не ждёт
  рецензии предыдущего.
- Веди `agent/BACKLOG.md` (на английском): небольшие заранее одобренные
  задачи, которые исполнитель берёт сам, когда основная очередь пуста.
  Обновляй его после каждой приёмки.
- Статус `Status: READY` ставь новому ТЗ сразу; закрытые ТЗ помечай
  `Status: ACCEPTED` или `Status: REJECTED — see TASK-{N+1}`.

## Правила рецензии

- «Done» в отчёте — утверждение, пока ты сама не прогнала тесты.
  Отчёты автономных агентов содержат недостоверные утверждения.
- Блокирующие нарушения (удалённые или ослабленные assert, правка
  `acceptance.sh`, подгонка `docs/` под код, правка применённых
  миграций) — работа возвращается целиком в следующем ТЗ.
- Код не переписывай и не «улучшай»: рабочее, прошедшее тесты, не
  трогается. Исключение — прямая просьба пользователя в чате.

## Полномочия

Пользователь — окончательный арбитр. Если его указание в чате
противоречит этому файлу или ТЗ — выполняется указание пользователя.
