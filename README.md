# EquityLab

Персональный десктопный research-снапшот по эмитенту для частного инвестора.
По запросу тикера за один проход приложение собирает цены, фундаментал,
ownership, корпоративные действия, отраслевые метрики и дашборд по компании,
а LLM-чат на тех же данных отвечает на вопросы с цитатами на первоисточники.

Помимо отдельных компаний приложение поддерживает **отраслевую аналитику**
(peer comparison, секторные агрегаты, цикл индустрии) и **watchlist** —
базу отобранных эмитентов с расписанием обновления, в том числе массовым
пополнением через LLM.

Проект мульти-рыночный: MVP работает на рынках, где отчётность доступна
машиночитаемо (US/CA), архитектура изначально спроектирована под
расширение на новые рынки без переписывания.

**Репозиторий:** https://github.com/shemyakin925-ux/RusTerm
**Статус:** проектирование. Спецификация в этом README и в `/docs` —
источник истины; код приложения ещё не пишется.

## Быстрый старт

Программа — локальный CLI: данные хранит в собственном каталоге, ничего
не отправляет наружу. Установка и первый проход на синтетике:

```bash
git clone https://github.com/shemyakin925-ux/RusTerm.git
cd RusTerm
python3 -m pip install -e .                     # команда `rusterm` появится в PATH
# опционально: библиотеки форматов ручного импорта (PDF/DOCX/XLSX);
# без них ручной импорт честно отвечает format_unsupported значением
python3 -m pip install -e ".[documents]"
rusterm init                                    # каталог данных + миграции БД
rusterm demo                                    # синтетический демо-инструмент US-CLI-DEMO
rusterm ingest --instrument US-CLI-DEMO         # сбор: 2 документа, 6 фактов
rusterm snapshot --instrument US-CLI-DEMO       # снапшот: 3 меры, все со значениями
rusterm status                                  # «что у меня есть»: база, снапшоты, покрытие
rusterm coverage --instrument US-CLI-DEMO       # покрытие данных по блокам
rusterm export --instrument US-CLI-DEMO --format csv --out demo.csv
```

Данные лежат в текущем каталоге: `rusterm.db`, `raw/`, `logs/`, `exports/`.
Другой каталог — через `rusterm --root ~/rusterm-data init`.

**Настоящая компания.** Свою компанию добавляет команда `add` (пофамильно
и офлайн — с `--cik` и `--name`; с контактом в `~/.rusterm.env` достаточно
тикера):

```bash
rusterm add --ticker AAPL --market US --cik 320193 --name "Apple Inc."
rusterm watchlist add my --ticker AAPL --market US
rusterm ingest --watchlist my
```

**Настоящие данные (SEC EDGAR).** Источнику нужен контакт: создайте файл
`~/.rusterm.env` со строкой `RUSTERM_SEC_UA="Имя email@example.com"` —
после этого доступен `rusterm ingest ... --source edgar`.
Без файла сетевые команды честно сообщают, что путь недоступен. Котировки
остаются синтетическими, пока не выбран вендор (docs/adr/0008 — решение
за пользователем).

**Пустой блок — не баг.** `rusterm coverage` показывает `missing` с
причиной (`no_data:...`) — значит, данных по блоку нет, и это показано,
а не спрятано.

## 1. Назначение

Дать частному инвестору по любому тикеру (а позже — по отрасли и watchlist):

- полный research-снапшот: цена, фундаментал, ownership, корп.действия,
  governance-светофор, отраслевые метрики;
- peer comparison с прямыми конкурентами;
- графики, таблицы, диаграммы по всем блокам;
- LLM-чат с цитатами на первоисточники по собранным данным;
- diff между проходами: «что изменилось с прошлого обновления»;
- массовые операции с watchlist через LLM: добавить одну компанию,
  сектор из 20 эмитентов, индекс, или «все конкуренты компании X».

**Не цель MVP:** торговля, брокерская интеграция, real-time тики,
новостной стрим, облигации, деривативы, портфельная аналитика,
бэктест факторов.

---

## 2. Целевой пользователь

Частный инвестор с горизонтом от квартала, самостоятельно принимающий
решения, работающий с несколькими сотнями бумаг одновременно (расчётный
потолок MVP — 500). Не трейдер.
Приложение — замена ручного сбора по сайтам эмитентов, SEC EDGAR,
IR-разделам и Smart-Lab: один запрос тикера заменяет 2-3 часа
ручной работы.

## 3. Что показывает снапшот по компании

Каждый блок — с графиком или таблицей, где применимо. Все числа связаны
с источником: клик по числу → ссылка на конкретный отчёт / страницу / пункт.

### 3.1 Котировки и доходность
- График цены (свечной или линейный) + adjusted price overlay
- Total Return с момента первой доступной даты, за 1Y / 3Y / 5Y / 10Y
- Бенчмарк: соответствующий индекс (S&P 500 для US,
  TSX Composite для CA; настраивается пользователем)
- Drawdown / recovery от исторического максимума
- Объём торгов, short interest (если доступно)

### 3.2 Фундаментал
- Таблица за 5-10 лет: выручка, EBITDA, чистая прибыль, FCF, EPS,
  дивиденды на акцию
- Мультипликаторы: P/E, EV/EBITDA, P/B, P/S, FCF yield, dividend yield
- Рост: 1Y / 3Y / 5Y CAGR по выручке и прибыли
- ROIC, ROE, маржинальность (gross / operating / net), asset turnover
- Долг: net debt, net debt / EBITDA, interest coverage
- Сегменты (если раскрывает) — таблица + sankey-диаграмма

### 3.3 Секторные метрики
Подбираются автоматически по сектору / индустрии эмитента. Полный
каталог — в `docs/industry-metrics/`. Ниже примеры.

**Нефтегаз и энергетика:** добыча vs запасы (R/P ratio), себестоимость
добычи ($/bbl), lifting cost, F&D cost, refining margin, downstream
utilization, net debt / EBITDAX, reserve life, capex intensity.

**Добыча и металлы:** AISC per ounce (золото), cash cost per tonne
(медь, железорудная руда), reserve grade, mine life, stripping ratio,
by-product credit, географическая экспозиция.

**Банки:** NIM, NII growth, CoR (cost of risk), CIR, CET1 / Tier 1 / CAR,
LDR, LCR, NPL ratio и NPL coverage, yield on assets, cost of liabilities,
spread, mix кредитного портфеля по сегментам.

**Страхование:** combined ratio (loss + expense), underwriting result,
investment yield, solvency ratio, reserve adequacy.

**REITs / недвижимость:** FFO, AFFO, AFFO / share, NOI по объектам,
occupancy rate, WALT, cap rate, NAV / share с premium / discount, same-property
NOI growth, tenant concentration, lease expiry schedule, gearing, ICR, LTV.

**Телеком:** ARPU, churn rate, subscriber growth (net adds), market share,
capex intensity, opex per subscriber, spectrum holdings (MHz по диапазонам),
5G coverage %, fiber homes passed, EBITDA - capex, postpaid vs prepaid mix.

**Utilities (regulated):** regulated vs unregulated asset base mix,
allowed ROE vs actual ROE, rate base growth, capex plan / rate base,
debt / capital, FFO / debt, renewable generation mix, capacity factor.

**Авиакомпании:** ASK (available seat km), RPK (revenue passenger km),
load factor, yield per RPK, RASK, CASK, fleet age, fuel efficiency
(litres per ASK), fuel hedging % на следующие 12 мес, ancillary revenue
per passenger.

**Морской транспорт (танкеры, контейнеровозы, балкеры):**
- **Revenue per ship** по классу судна (VLCC, Suezmax, Aframax, MR,
  LR1, LR2, Capesize, Panamax, Ultramax, Supramax)
- **TCE (time charter equivalent) per day** по классу — основная
  метрика доходности
- **Fleet utilization %**, off-hire days
- **OPEX per ship per day** по классу и возрасту
- **Daily vessel OPEX** vs market TCE — валовая маржа на судно
- **Vessel breakeven rate** — TCE, при которой компания на нуле
  (OPEX + финансирование + G&A, делённые на количество судов)
- **Spot vs time-charter exposure %** (краткосрочные vs длинные контракты)
- **Fleet age profile**, средний остаточный срок службы
- **Orderbook / fleet ratio %** — давление на фрахтовые ставки
- **Newbuilding price index**, **second-hand price index** по классам
- **Bunker cost / revenue %** — зависимость от цен на мазут
- **Scrapping age profile** — когда флот «созреет» для выбытия
- **Экологические показатели:** CII (Carbon Intensity Indicator) по судам,
  расходы на scrubber'ы, готовность к IMO 2020 / 2023
- **Port congestion exposure** (для контейнеровозов — TEU в ожидании)

Каталог расширяется: добавление нового сектора = новый файл в
`docs/industry-metrics/` с метриками, источниками, сложностями
извлечения, golden-file тестами.

### 3.4 Ownership
- Таблица top-10 акционеров: класс акций, %, тип
  (институционал / инсайдер / государство / частный)
- Free float, инсайдерская доля
- Изменения ownership за период (insider buying / selling — Form 4 для US,
  SEDAR+ раскрытия для CA)

### 3.5 Корпоративные действия
- Сплиты, обратные сплиты, допэмиссии, байбэки (объявленный vs
  фактически выкуплено, что сделано с казначейским пакетом)
- Дивиденды: дата отсечки, дата выплаты, размер, тип (обычные /
  специальные / franked для AU — когда появится)
- M&A (поглощения, выделения spin-off, делистинги)
- Смена тикера, перерегистрация, конвертация расписок

### 3.6 Governance-светофор
Не полный governance-скор, а простой набор индикаторов. Каждый — зелёный /
жёлтый / красный с коротким обоснованием.

- Доля независимых директоров (%)
- Совмещение CEO / Chair (да / нет, с какой даты)
- Связанные сделки (related-party transactions) выше порога — объём
  и одобрение
- Insider trading net (покупки минус продажи, USD) за последние 6 / 12 мес
- Аудитор, смена аудитора за последние 5 лет

**Доступность по рынкам неодинакова.** Структурированный источник состава
совета, связанных сделок и сделок инсайдеров есть только у US — DEF 14A и
Form 4. У CA машиночитаемого аналога нет: эти поля извлекаются из
годового отчёта в PDF, поэтому полнота ниже, а доля `null` выше. Блок при
этом не блокирует сборку снапшота — недостающий индикатор показывается как
«нет данных» с причиной, и никогда не как зелёный.

### 3.7 Peer comparison
- Таблица peer-компаний с ключевыми метриками бок о бок
- Бокс-плот P/E, EV/EBITDA, FCF yield, ROIC по сектору — текущее
  значение компании подсвечено
- Радарная диаграмма по 5-7 метрикам (компания vs среднее по peer set)

### 3.8 What's Changed (diff с прошлым проходом)
- Цена, мультипликаторы, ownership, события — diff-лист
- «С момента прошлого обновления: 3 новых раскрытия, 1 insider buy,
  дивдоходность выросла с 2.1% до 2.4%, новый guidance по capex»

### 3.9 LLM-чат с цитатами
Контекст чата = все собранные данные по тикеру + ссылки на
первоисточники. Каждый числовой ответ LLM — со ссылкой на конкретный
отчёт / страницу / пункт. Кнопка «показать источник» рядом с числом.
Предустановленные промпты:
- «Объясни последний 10-K простым языком»
- «Что менялось в дивполитике за 3 года?»
- «Сравни с peer X по маржинальности»
- «Что LLM думает про риски этого эмитента?»

## 4. Что показывает отраслевая аналитика (Industry View)

Отдельный раздел приложения, доступен по клику на сектор / индустрию
в любом месте UI. Это **слой выше снапшота**: не одна компания, а вся
отрасль сразу.

### 4.1 Peer comparison table
Все компании сектора рядом по ключевым метрикам с фильтрами, сортировкой,
выбором набора колонок. По умолчанию — стандартный набор (выручка,
EBITDA, маржа, ROIC, P/E, EV/EBITDA, дивдоходность), расширяется
отраслевыми метриками из каталога.

### 4.2 Sector aggregate
- Суммарная выручка сектора
- Суммарный capex
- Медианный ROIC, P/E, FCF yield
- Дисперсия оценок (разброс P/E — индикатор «перегрет ли сектор»)

### 4.3 Цикл индустрии
Где отрасль сейчас — early / mid / late / down cycle. Индикаторы
(набор зависит от отрасли):
- Spread между спотовыми и долгосрочными ставками (танкеры)
- Загрузка мощностей (авиакомпании, отели, нефтепереработка)
- Days inventory / days sales outstanding по сектору
- Capex / depreciation (индикатор инвестиционного цикла)
- Orderbook / fleet ratio (судостроение)
- Days inventory у дилеров (автопром)

### 4.4 Концентрация
- Топ-N эмитентов занимают X% выручки сектора
- Индекс Херфиндаля-Хиршмана по капитализации
- Доля топ-5 в прибыли сектора

### 4.5 Регуляторные события
Лента изменений регулирования, тарифов, лицензий, штрафов, преференций
по сектору. Извлекается из раскрытий и новостных релизов.

### 4.6 Лидеры и аутсайдеры
- Кто растёт быстрее (выручка / EBITDA CAGR)
- У кого лучше маржа (gross / operating / net)
- У кого самый дешёвый по мультипликаторам
- У кого самые большие байбэки

### 4.7 LLM-чат «про отрасль»
Отдельный режим с контекстом: все компании сектора + последние N событий
по индустрии. Предустановленные промпты:
- «Сравни топ-5 компаний сектора по маржинальности»
- «Что общего у лидеров роста?»
- «Какие регуляторные риски у сектора сейчас?»

### 4.8 Пример для морского транспорта
- Spot TCE по классам судов (VLCC, Suezmax, Capesize, Panamax) — таблица
  + график за 5 лет
- Мировой orderbook по классам, % от текущего флота, прогноз давления
  на ставки
- Топ-10 операторов по dwt, их доля в мировом флоте
- Распределение возраста флота по компаниям — кто «созрел» для выбытия
- Bunker spread (HSFO vs VLSFO) — стоимость IMO compliance

### 4.9 Пример для банков
- NIM evolution за 5 лет по топ-10 банкам выбранного региона
- CoR trend — кто ужесточает, кто смягчает
- CET1 ratios scatter vs ROE — кто эффективнее использует капитал
- Loan book growth по сегментам (retail mortgage / corporate / SME)

## 5. Watchlist: база отобранных компаний

Центральный объект приложения. Пользователь заранее формирует список
интересующих эмитентов, приложение по расписанию или по запросу
обновляет по ним данные.

### 5.1 Структура watchlist
- **name** — название списка
- **description** — описание назначения
- **tickers** — список тикеров, или
- **sectors / filters** — динамический набор
  (например, все компании Maritime с cap > 500M)
- **update_schedule** — weekly / monthly / manual
- **last_update** — когда последний раз обновлялся
- **coverage** — % эмитентов с полным снапшотом

### 5.2 Группы (collections)
- Именованные группы: «Банки Европы», «Золотодобытчики»,
  «Танкерные компании»
- Группа = статический список тикеров или динамический фильтр
- Группа обновляется по общему расписанию, можно переопределить
- Группа может пересекаться с другой группой — нормально

### 5.3 Покрытие (coverage)
По каждой компании в watchlist видно, какие блоки снапшота готовы:
- цены ✓
- фундаментал ✓
- ownership ✓
- governance ✓
- LLM-summary ✓

Если не готово — причина:
- отчёт ещё не опубликован
- peer set не определён
- провайдер вернул ошибку
- LLM не смог извлечь событие (требуется ручная верификация)

### 5.4 История watchlist
- Каждое изменение списка = новая версия
- Можно откатиться: «верни watchlist к состоянию на 1 сентября»
- История видна в UI: «в watchlist добавили FRO 15 сентября,
  удалили DHT 20 сентября»

### 5.5 Импорт / экспорт
- Экспорт watchlist в CSV / JSON — делиться с коллегами или
  переносить между инсталляциями
- Импорт из CSV: `ticker, market, sector, note`
- Импорт из портфельных трекеров (на будущее): Interactive Brokers,
  Trading 212

### 5.6 Сценарии использования
- **Регулярный разбор портфеля:** раз в неделю обновлять снапшоты
  по сотне бумаг — посмотреть, что изменилось
- **Разовое изучение отрасли:** добавить сектор, дождаться сбора,
  изучать Industry View
- **Сравнение стратегий:** три параллельных watchlist —
  conservative / aggressive / dividend

## 6. LLM: пополнение базы и массовые операции

Это **отдельный режим** LLM-чата. Не «спросить про AAPL», а
«пополнить watchlist и запустить сбор».

### 6.1 Добавить конкретные компании
```
Пользователь: "Добавь в watchlist Frontline (FRO), DHT Holdings (DHT),
                Euronav (EURN), International Seaways (INSW), Torm (TRMD).
                Сектор — танкерные компании."

LLM:
  - Intent: add_tickers_to_watchlist
  - Резолвит тикеры через MarketDataProvider
  - Проверяет сектор, биржу, ISIN
  - Подтверждение: "Будут добавлены 5 компаний, сектор Maritime / Tanker.
    Запустить первичный сбор данных?"
  - Пользователь: "Да"
  - LLM добавляет в watchlist, ставит задачу на сбор
```

### 6.2 Добавить целый сектор
```
Пользователь: "Добавь в watchlist все танкерные компании
                с капитализацией от 500M до 5B."

LLM:
  - Запрашивает у провайдеров список компаний сектора Maritime
  - Применяет фильтр по капитализации
  - Возвращает список для подтверждения: "Найдено 12 компаний:
    [Frontline, DHT, Euronav, INSW, Torm, Scorpio Tankers, ...].
    Добавить в watchlist?"
  - После подтверждения: добавление + запуск сбора
```

### 6.3 Добавить индекс / ETF-холдеры
```
Пользователь: "Добавь все компании из S&P 500 сектора Healthcare."

LLM:
  - Получает список из индекса
  - Фильтрует по сектору
  - Подтверждение + добавление
```

### 6.4 Добавить «конкурентов» существующей компании
```
Пользователь: "Найди всех конкурентов Frontline и добавь в watchlist."

LLM:
  - Анализирует описание деятельности Frontline (из снапшота)
  - Через LLM + провайдеры ищет похожие компании
  - Возвращает список с кратким описанием каждой
  - Подтверждение + добавление
```

### 6.5 Массовое обновление LLM-summary
```
Пользователь: "Обнови summary по всем компаниям watchlist —
                последние изменения за неделю."

LLM (для каждой компании параллельно):
  - Берёт diff снапшота vs предыдущий проход
  - Генерирует summary: "Цена +3.2%, выше consensus. Опубликован Q3
    отчёт: выручка +5%, EBITDA in line. Инсайдер Smith купил 10K акций.
    Дивдоходность осталась 8.1%."
```

### 6.6 Принципы массовых операций
- Все операции требуют явного подтверждения пользователя:
  dry-run → review → execute
- LLM никогда не пишет числа — только текст. Числа из снапшота
- Каждое действие логируется с возможностью отката
- Если LLM не уверен в результате (например, не может надёжно
  определить сектор компании) — запрашивает уточнение, не действует
  наугад

## 7. Источники данных по рынкам MVP

MVP — три рынка, где отчётность доступна машиночитаемо.

| Рынок | Источники отчётов | Цены |
|---|---|---|
| 🇺🇸 США | SEC EDGAR (10-K, 10-Q, 8-K, DEF 14A, Form 4) | FMP / Polygon / Yahoo |
| 🇨🇦 Канада | SEDAR+ (AIF, MD&A, annual / interim, news releases) | FMP / Yahoo |

**Порядок в колонке «Цены» — это порядок фолбэка,** а не список равноправных
вариантов: первый провайдер основной, следующий берётся при ошибке, пустом
ответе или исчерпании лимита, и в факте фиксируется, кто именно ответил.
Выбор конкретного вендора на первую позицию — при старте разработки, по
соотношению лимитов и качества; сам принцип фолбэка от этого выбора
не зависит.

**Ленты релизов** — часть источников отчётов, а не отдельный вендор: 8-K для
US, news releases SEDAR+ для CA. Из них питается блок §4.5
(регуляторные события). Отдельного новостного агрегатора в MVP нет, и
событие, не попавшее в раскрытие эмитента или в его релиз, в ленту
не попадёт — граница осознанная, см. §12.

## 10. Архитектура

Слои сверху вниз; каждый зависит только от нижнего. Стабильность этих
интерфейсов — то, что делает добавление нового рынка дешёвым.

```
UI (десктоп)
  Снапшот компании · Industry View · Watchlist · LLM-чат
        |
Слой сборки (snapshot builder)
  собирает блоки снапшота, считает метрики, ведёт method_version и diff
        |
Слой нормализации
  единый data dictionary: тикер -> инструмент, статьи отчётности,
  валюты, периоды, отраслевая классификация, пиры
        |
Слой провайдеров (MarketDataProvider / DisclosuresProvider)
  us_sec_edgar · uk_companies_house · ca_sedar · провайдеры цен
        |
Хранилище
  store/raw (content-addressed) + манифесты JSONL + SQLite
```

Правила:

- Провайдер ничего не знает про UI, UI ничего не знает про провайдера —
  общение только через нормализованные модели.
- LLM — потребитель слоя сборки, а не источник данных: доступ к цифрам
  только через инструменты, читающие готовый снапшот.
- Любой расчёт детерминирован: те же сырые файлы плюс тот же
  `method_version` дают тот же результат.
- Сбор идемпотентен: повторный проход не переписывает историю,
  а добавляет версию.
- Ошибка одного провайдера не роняет проход — блок снапшота помечается
  как недоступный с причиной (см. coverage, §5.3).

## 11. Развёртывание, стек и структура репозитория

### 11.1 Модель развёртывания

RusTerm — **локальное однопользовательское приложение со своим интерфейсом,
не сервис**. Ставится на компьютер, работает без учётной записи, регистрации
и серверной части.

- Все данные — сырьё, база, watchlist, настройки — лежат в одном каталоге
  на диске пользователя. **У каждого пользователя свой набор данных**;
  обмена между установками нет.
- Наружу приложение ходит только за данными: провайдеры цен и раскрытия,
  endpoint LLM. Ни телеметрии, ни отправки watchlist или снапшотов на сторону.
- Резервная копия — копия каталога. Перенос на другой компьютер — копирование
  каталога. Обмен списками между установками — только явным экспортом
  CSV / JSON (§5.5).
- Ключ LLM хранится в системном хранилище секретов, не в конфиге и не в репо.

```
<app-data>/              каталог данных, путь настраивается
  rusterm.db             SQLite: факты, снапшоты, watchlist, версии, история
  raw/store/<2>/<sha256> сырые объекты, как получены от источника
  raw/manifests/*.jsonl  журнал загрузок
  exports/               выгрузки CSV / Excel
  logs/
  config.toml            настройки
```

Один процесс, один писатель в базу. Многопользовательский режим, общий сервер
и облачная синхронизация не заложены и не планируются — они меняют требования
к СУБД, правам доступа и лицензированию данных. Обоснование выбора SQLite
вместо серверной СУБД — ADR-0003.

### 11.2 Стек

Выбор оболочки и графики зафиксирован ADR-0004, хранилища — ADR-0003;
остальное подтверждается ADR при старте разработки.

| Слой | Выбор | Основание |
|---|---|---|
| Язык | Python 3.12+ | экосистема XBRL, парсинга отчётности, pandas |
| Метаданные | SQLite, один файл | ~4 млн строк при 500 бумагах — ADR-0003 |
| Сырьё | файловое content-addressed store | дедупликация и версионирование бесплатно |
| UI | нативный десктоп на PySide6 (Qt), один процесс с ядром | ADR-0004 |
| Графики | pyqtgraph (ряды), QtCharts (столбцы, box-plot) | ADR-0004 |
| Сборка | PyInstaller -> .app | подпись нужна только при раздаче |
| Тесты | pytest + golden-file на все формулы | формула меняется только с эталоном |
| LLM | внешний endpoint, ключ в настройках | см. §9 |

## 13. Хранение и версионирование

- **Сырые файлы** в content-addressed хранилище:
  `store/raw/store/<2>/<sha256>` — дедупликация, версионирование
  бесплатно (изменённая страница = новый объект)
- **Манифесты** в JSONL с полями `provider`, `market`,
  `instrument_id`, `ts`, `status`, `bytes`, `sha256`
- **Факты, снапшоты и watchlist** в SQLite — один файл в каталоге данных
- **`method_version`** на каждом расчёте — изменение весов / формул
  не молча переписывает историю, пересчёт = новая версия
- **Golden-file тесты** на все финансовые формулы, веса governance,
  отраслевые метрики — формула меняется только вместе с эталоном
- **История watchlist** — каждое изменение = новая версия,
  откат поддерживается

## 16. Правовое

**Текущий режим:** личное использование, приложение не раздаётся
третьим лицам. В этом режиме ограничений по данным нет.

При выходе в публичный режим вопрос лицензирования данных становится
блокирующим:
- Регуляторные и агрегаторские источники — право на перераспространение
  проверяется по каждому отдельно
- Парсинг источников — соблюдение robots.txt и разумный rate limit
- Governance / sector scoring — формулировка «оценка на основе
  публично раскрытых фактов», обязательная ссылка на первоисточник

Решение фиксируется в ADR до выхода в публичный режим, не после.
