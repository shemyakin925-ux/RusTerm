# Проверка RusTerm: автомат + живой осмотр

Тесты зелёные ≠ продукт работает. Отчёт исполнителя ≠ факт. Решают
прогон и **скриншоты, которые ты сама посмотрела** (Read по PNG).

## 0. Какой код смотреть (сначала!)

Пользователь запускает `~/EquityLab/app` (ветка `agent/night-11`), а не
этот worktree — он может отставать на десятки ТЗ. `look.py` по умолчанию
берёт `~/EquityLab/app`; другой код — `--code DIR`. Перед правками:
`git -C ~/EquityLab/app log --oneline -1` и `agent/BATON.json` — если
ход у исполнителя, в `night-11` не писать: правки — отдельной веткой от
`origin/agent/night-11` (`git worktree add`), их вливает координатор,
когда ход вернётся. Проверь свежее `agent/TASK-*.md`: дефект, уже
выданный исполнителю, не чинить второй раз.

Хук коммита: `core.hooksPath` указывает на главную копию (другая ветка);
НЕ коммить через `git -c core.hooksPath=…`: `-c` наследуется
вложенными коммитами тестов, и приёмка запускает сама себя рекурсивно
(01.10.2026: десятки вложенных pytest, пришлось убивать). Если хук
главной копии не подходит ветке — `bash agent/selfcheck.sh` вручную и
спросить пользователя про `--no-verify`. Сообщение заранее положить в
`$(git rev-parse --git-path COMMIT_EDITMSG)` (правило P1 читает
«ЗАМЕНА-БУЛАВКИ/ПОЧЕМУ СИЛЬНЕЕ» оттуда). Хук идёт 10+ минут. После прогона проверь `core.bare` главного `.git/config` —
однажды тесты оставили там `true`.

## 1. Автоматическая часть (≈2 мин)

Схема базы ниже той, что ждёт программа (баннер «обновите: rusterm … init»)
— это первая находка: пользователь видит именно это.

## 2. Живой осмотр окна (главное)

```bash
python3 .claude/skills/rusterm-check/look.py --root ~/EquityLab/data \
  --out "$TMPDIR/rusterm-look" --companies 12
```

Скрипт строит настоящее окно (`rusterm.desktop.window._build_window`)
офскрин на реальной базе, выбирает компании из дерева, проходит все
вкладки, сохраняет PNG и `report.json` (тексты меток, все ячейки таблиц,
доля пустых, лог Qt). Печатает сводку `компания | вкладка | empty X/Y`.

Затем **обязательно**:

1. Открой Read-ом `00-start.png` и по одному PNG на каждую вкладку
   (минимум две компании из разных секторов).
2. Для каждого скриншота ответь себе: что пользователь увидит
   сломанным? Чек-лист:
   - баннеры/плейсхолдеры с ошибкой (`недоступна`, `Disputed`, `ждёт
     двери`, `обновите`, `списков нет` при непустом дереве);
   - таблицы: колонки целиком из «нет данных» (история-заглушка),
     обрезанный текст «нет …», сырые числа вида `10553000000` или
     `0.0042` вместо `10,55 млрд USD` / `0,42 %`;
   - график «нет данных» или одна точка;
   - кнопки, которые неактивны без причины;
   - empty ≥ 80 % в сводке — продукт фактически пуст.
3. Если пользователь прислал свой скриншот — сравни с ним; расхождение
   (другая схема, другие числа) значит, что он запускает другую
   сборку/каталог — выясни какую (`which rusterm`, ярлык `.app`).

Нужен реальный экран (сеть, «Собрать»)? Запусти
`python3 -m rusterm.desktop --root ~/EquityLab/data` и смотри через
computer-use (request_access к `Python`).

## 4. Итог

Таблица «что видно → почему → где в коде (`file:line`)». Мелкие
дефекты отображения, о которых просит пользователь, можно чинить сразу
(+ тесты); всё остальное — пунктами следующего `agent/TASK-*.md` с
«Done when» = команда `look.py` + проверяемое условие на `report.json`
(напр. `empty_or_no_data / cells < 0.5` на вкладке «Компания»).

## 5. Сверка с аналогами (пользователь хочет «похоже на них»)

Эталоны: Koyfin, TIKR, Finviz, Yahoo Finance / Morningstar (вкладка
Financials), Smart-Lab (мультипликаторы). Если есть сеть — открой
страницу той же компании (напр. DELL) во встроенном браузере и положи
скриншот рядом со своим. Общие для них правила, по которым судить окно:

- годы слева направо **от старых к новым**, последняя колонка — TTM/«сейчас»;
- пусто — «—», а не «нет данных» в каждой ячейке; колонки без данных
  вообще не показываются;
- деньги — в млн/млрд, единица один раз в заголовке строки или раздела
  («USD, млрд»), числа выровнены вправо, разделитель тысяч;
- доли — %, мультипликаторы — «×», 1–2 знака после запятой;
- меры сгруппированы разделами (Оценка · Рентабельность · Долг ·
  Денежный поток · Доходность), читаемые русские названия вместо
  `ev_ebitda`, подсказка с формулой;
- график по выбранной строке — столбики по годам, а не одна точка;
- значения сравнимы с аналогами (Yahoo/Finviz) с точностью ~5 %:
  расхождение больше — находка.

Каждое отличие — строка в итоговой таблице «у нас / у аналога / что
сделать».

### Заметки из прогона 01.10.2026
- Finviz и StockAnalysis отдают Cloudflare-проверку — не обходить.
  FMP-коннектор: `company/batch-market-cap` бесплатен (не для всех
  тикеров), `quote` — платный (ADR-0018: не использовать).
- Трассировка числа: `tui_model.card_rows(repos, "US-DELL")` → `measure_id`
  → `repos.snapshot.lineage_fact_ids` → `repos.fact.get_fact`;
  цены — таблица `price(instrument_id, date, close)`.
- Причины пустоты по мерам: тот же `card_rows`, поле `null_reason`.
